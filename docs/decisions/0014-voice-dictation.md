# 0014 - Dictation: local Whisper, on-device only

Status: proposed
Date: 2026-11-22

## Context
The user asked on 2026-11-22 that text fields where a person may write a lot offer writing by voice, with a button; powered by a local Whisper model downloaded from Hugging Face when the hardware allows, otherwise by a more classic transcription.

Forces: CLAUDE.md (zero budget, unsigned builds, disk C small, no plaintext user data or key material on disk, in logs or in process arguments; nothing irreversible without asking; never take focus or send input); ADR 0003 (data directory, encrypted store); ADR 0004 (two executables in one Velopack package, per-user install); DESIGN.md principles 5 (next frame) and 7 (undo over asking). Spoken words are user content: the audio and the text it becomes fall under the plaintext rule.

## Decision

### 1. Where: every multi-line editor, nothing else
The microphone button is in each multi-line editor (DESIGN 5): descriptions of projects, epics and topics; current state; a timeline entry being edited (the human never adds entries, user ruling 2026-11-22); quick capture, the inbox capture and a note being edited; a memory's body and a document's body; the question composer and the answer editor. Not in titles, summaries, the person field, search inputs, the terminal or the chat. The placement, states and keys are in `docs/design/components-voice.md`.

### 2. Never off the machine
Audio is recognised on this computer or not at all. No cloud recogniser, whatever the OS offers: Windows' dictation grammar and voice typing go to Microsoft's service (and the WinRT API is closed to an unpackaged app anyway); macOS' server-based `SFSpeechRecognizer` is never used (`requiresOnDeviceRecognition` is always set). Acta makes no network call for dictation except the model download the user clicks (4).

### 3. Engines and the choice
- **Whisper** (whisper.cpp through whisper-rs) on every OS: the default and the only engine on Windows and Linux.
- **macOS recogniser**: `SFSpeechRecognizer` on the device, through `objc2-speech`, offered in Settings on a Mac where `supportsOnDeviceRecognition` is true for the chosen language. Nothing to download; less accurate; one more permission prompt (speech recognition) on top of the microphone's, both repeated after each update while builds are ad-hoc signed. It is not the default; first use proposes it only when the free disk space cannot hold the smallest Whisper model plus 1 GB, or under the hardware floor. The Swift-only SpeechAnalyzer is not used (it would bring Swift into the build); revisit if `objc2` gains a binding.
- **Windows and Linux "classic" fallback: none exists on the device.** The fallback is the smallest Whisper model on the processor (Tiny, 31 MB), which runs on any machine Acta supports. When even that cannot run (under 2 GB of total memory), the first-use dialog says so with the reason and offers only Close; nothing is downloaded.
- **Settings > Voice > Dictation**: "Whisper, on this computer" / "macOS recogniser, on this computer" (macOS only) / "Off". The engine sits behind one trait so the UI, tests and engines are independent (5).

### 4. Models: the ladder, the download, the disk
One file per model, multilingual only (English and French in one model), quantized:

| Model | File | Size | Recommended when |
|-------|------|------|------------------|
| Large turbo | `ggml-large-v3-turbo-q5_0.bin` | 574 MB | The GPU tier: Apple Silicon (Metal) with 8 GB or more of memory; from step 2 of the build, a Vulkan GPU with 4 GB or more of dedicated memory (Windows, Linux) |
| Small | `ggml-small-q5_1.bin` | 190 MB | The CPU tier: 8 GB or more of memory, 4 or more physical cores, AVX2 and FMA on x86-64 or any arm64 |
| Base | `ggml-base-q5_1.bin` | 60 MB | A weaker CPU: 4 GB or more of memory, otherwise below the CPU tier |
| Tiny | `ggml-tiny-q5_1.bin` | 31 MB | The floor: 2 GB or more of memory (French is rough at this size: 41% WER on FLEURS) |

- **Detection** (`acta-core::voice::hardware`, pure over a `Machine` struct filled by `sysinfo`, `is_x86_feature_detected!`, `cfg(target_arch)`, `sysctl.proc_translated` on macOS (Rosetta counts as x86), DXGI on Windows for the Vulkan step): it returns the recommended model and its one-line reason. The recommendation is shown; the user can pick any model; Acta never switches by itself.
- **Download only on a click** that names the size ("Download 190 MB"), from the first-use dialog or Settings. Never at startup, never in the background unasked, never two at once. The free space of the models' disk is shown before; a download that would leave less than 1 GB free is refused.
- **Integrity.** Each model is a compile-time constant: file name, size, SHA-256 (the table in Context). The URL is `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/<file>`; redirects to Hugging Face's CDN are followed over HTTPS only. The body streams through SHA-256 into `<file>.part`; a size or hash mismatch deletes the part file and fails ("The file did not match. Try again later."). A `.part` left by an interrupted download resumes with a `Range` request after its bytes are re-hashed. Success is `fsync` then rename. A weekly CI job reads the HF tree API (no download) and fails if a constant no longer matches, so a re-uploaded model is caught before users hit it.
- **Where.** `<data dir>/models/` (ADR 0003's data directory, outside the Velopack root so updates keep it). Model files are public weights, not user data: plaintext is fine; they are not in snapshots, exports or backups. Settings shows the folder, the space used, the free space, and "Delete model" per model. Uninstalling Acta leaves the data directory, as for the database; the uninstall note and Settings say so.
- **Load check.** The size and modification time recorded after the hash check are compared at each load; any difference re-hashes before use.
- **Silero VAD** (`ggml-silero-v6.2.0.bin`, 885 KB, MIT) ships inside the app package with its hash checked at build time; it is not downloaded.
- HTTP uses the `ureq` client Acta already has (rustls), with a 30 s connect and read timeout, the system proxy as the updater does, and no cookies or token.

### 5. Architecture: a worker process, one trait
- **Trait** in `acta-core::voice`: `Engine { fn start(&mut self, lang: Lang) -> Result<()>; fn feed(&mut self, phrase: &[f32]) -> Result<Text>; fn stop(&mut self); }` over 16 kHz mono `f32` phrases; implementations `WhisperWorker`, `MacRecognizer`, and `FakeEngine` for tests. Phrase segmentation, anchors, insertion, limits and states live above the trait and are engine-independent.
- **Capture** (`acta-app`, cpal): the device's stream into a lock-free ring on the real-time thread; a capture thread downmixes, resamples to 16 kHz with rubato, computes the level for the bar, and cuts phrases with an energy detector (adaptive noise floor; a phrase ends after 600 ms under it, or at 25 s, under Whisper's 30 s window).
- **Whisper runs in a child process**: the GUI executable started with a hidden `--voice-worker` argument (checked first in `main`, before any window, single-instance lock or update step). Phrases go in over its stdin and text comes back over its stdout as length-prefixed frames; pipes are memory, not disk; the argument carries no data. Reasons: a `GGML_ASSERT` or a driver fault aborts the worker, not the window with the user's drafts; the model's memory (up to ~1 GB) is returned to the system when the worker exits after 5 minutes idle; GPU drivers are never loaded into the GUI process. The worker starts when a take starts, so loading the model overlaps the first words. The CLI executable (hooks, MCP) does not link whisper and does not grow.
- **Per phrase**: Whisper with Silero VAD on (non-speech dropped, the main guard against invented text), `no_context` off within a take and the take's previous text as the prompt (punctuation and capitals carry over), reset between takes; temperature fallback off; a phrase whose VAD finds no speech is never decoded. Threads: physical cores minus one, at most 8.
- **Language**: "English or French, detected" runs whisper's language detection on the first phrase of a take and keeps the more likely of `en` and `fr` for the take; "English" and "French" force it. The macOS recogniser has no detection: "detected" uses the interface language.
- **GPU**: step 1 ships CPU everywhere and Metal on Apple Silicon (the `metal` feature, library embedded). Step 2 adds Vulkan for Windows and Linux only after a spike proves a build where a machine without `vulkan-1` still dictates on the CPU (a second worker executable linked with Vulkan and started first, falling back to the CPU worker when it cannot start or reports no device; or ggml's dynamic backends with a custom build) and measures the package size it adds; that spike amends ADR 0004 if it adds an executable. CUDA (runtime libraries of hundreds of MB, NVIDIA only) and CoreML (a second converted model per size, Python to make it) are out.

### 6. Taking dictation
- **One key, two gestures, no setting**: `Mod+Shift+Space` (or the button) pressed briefly toggles; held 300 ms or more it is push-to-talk until release. Only inside the editors of 1.
- **Text is written phrase by phrase, never rewritten**: each phrase lands at the anchor (the caret where the take started, tracked through edits) when a pause ends it. No live partial words: Whisper has none without re-decoding a sliding window, which on a CPU would cost several times the audio, and words that change under the reader break principle 6 in spirit. The macOS recogniser's partial results are ignored the same way; its final result per phrase is written.
- **Punctuation**: Whisper's own. No spoken commands ("new line", "full stop") in v1; revisit if asked.
- **Limits**: 60 s without speech and 10 minutes per take stop it; one take at a time in the app; a take is one undo step.

### 7. Privacy of audio and text
- Audio exists only in memory: the cpal ring, the capture thread's phrase buffers and the worker's input. Each buffer is zeroed when its phrase is done (`zeroize`), and the whole take's at stop. Never a file, a temporary file, a pipe to anything but the worker, the clipboard, a log line or a process argument.
- Neither audio nor text is logged: whisper.cpp's log callback is set to a function that drops everything; the worker's stderr is read and discarded, never forwarded to Acta's diagnostic log; Acta's own log records only states and errors ("take started", "worker exited with code 3"), never lengths of text or audio.
- Crash dumps: the worker calls `WerSetFlags(WER_FAULT_REPORTING_FLAG_NOHEAP)` on Windows and `prctl(PR_SET_DUMPABLE, 0)` on Linux; macOS crash reports hold no memory contents.
- The text is user content from the moment it is written into the editor, and from there follows the rules every draft and record already follows (request 15, ADR 0003).

### 8. Permissions
- **macOS**: the `Info.plist` gains `NSMicrophoneUsageDescription` ("Acta turns what you say into text, on this Mac.") and `NSSpeechRecognitionUsageDescription` (for the macOS recogniser), in English and French (`InfoPlist.strings`). The permission is asked on the first take, not at launch. Ad-hoc builds re-ask after each update (Context); the first take after an update says nothing more than the system's prompt.
- **Windows**: nothing to declare. A denied capture is detected from the error of the stream's start and shown with "Open privacy settings" (`ms-settings:privacy-microphone`). When Windows' per-app prompts reach release, the prompt names Acta as "Unsigned"; a device whose policy denies unsigned apps gets the same blocked line.
- **Linux**: none; a missing ALSA device is "No microphone was found."

### 9. What Claude Code sees
Nothing new. Dictated text is text in a record: no flag, no source field, no MCP tool, no CLI command, no hook, no change to ADR 0005. The agent cannot start or read dictation.

## Alternatives
- Windows `SpeechRecognizer` dictation or voice typing as the classic fallback: audio goes to Microsoft's service, and the API needs package identity Acta does not have.
- macOS server-based `SFSpeechRecognizer`: audio goes to Apple; never used.
- Cloud speech APIs (Azure, OpenAI, Deepgram): audio leaves the machine, and they cost money.
- Whisper in the GUI process: an abort in ggml or a GPU driver would take the window and its drafts with it, and the model's memory would stay until quit.
- Live partial text by re-decoding a sliding window (whisper.cpp `stream`): several times the compute on a CPU, and words that change under the reader.
- Bundling a model in the installer: 60 to 574 MB in every download and every update's full package, for a feature not everyone uses.
- `medium` (539 MB q5_0): turbo is the same size, more accurate and faster.
- English-only `.en` models and distil-whisper: French is half of Acta's languages.
- CUDA, CoreML: size and extra models (5).
- Vosk or other small offline recognisers as the Windows and Linux fallback: separate per-language models of similar size to Whisper Tiny and Base with lower French accuracy (not measured here); one engine family is less to build and test.
- A separate push-to-talk / toggle setting: both gestures on one key cost no setting.

## Consequences
- The GUI executable grows by whisper.cpp (and the Metal library on macOS); the size is measured in step 1 and recorded here. Budget: under 10 MB per platform; above it, revisit (a separate worker executable downloaded with the first model).
- CI runners need CMake and a C++ compiler (present on GitHub's images) and, on Linux, `libasound2-dev`; bindgen is avoided with `WHISPER_DONT_GENERATE_BINDINGS=1` (no libclang). The local Windows build keeps `CARGO_TARGET_DIR` on a short path, which CMake also needs.
- whisper-rs trails whisper.cpp (1.8.3 vs 1.9.5) and moved to Codeberg; if it stalls, a thin own `-sys` crate over whisper.cpp's C API is the fallback (the API Acta uses is small).
- macOS users see the microphone prompt after every update until builds are signed with a stable identity; a free self-signed certificate kept by the release workflow might keep the designated requirement stable (unverified; it would also help ADR 0003's keychain) and is left to the release engineer.
- A 574 MB model on a small system disk: the dialog shows free space first and Settings deletes models; nothing downloads by itself.
- Revisit: when Windows exposes an on-device dictation API to unpackaged apps; when `objc2` binds SpeechAnalyzer; when whisper.cpp gains true streaming; if users ask for spoken commands or more languages (the models already cover them; only the Settings list and the detection pair would change).

## Addendum (2026-11-22): embedded only
The user: no secondary service like Ollama, installed or running; it must be embedded. So: whisper.cpp is compiled into Acta's own executable; nothing is installed besides the model file the user downloads; no server, no port, no background service, no autostart. The `--voice-worker` child is Acta.exe itself, started only while dictating or within 5 minutes after, tied to Acta's lifetime (job object with kill-on-close on Windows, parent-death signal on Linux, pipe EOF on macOS), so it never outlives Acta and never runs when dictation is off.

## Amendment (2026-11-22): steps 1 to 3 built
Built on `integration-engineer/voice` (core, downloader, worker). What changed from the text above, and what was measured:

- **x86-64 processors need AVX2 and FMA.** ggml picks its SIMD paths at compile time unless its dynamic backends are used, which whisper-rs cannot (Context). The build pins portable flags in `.cargo/config.toml`: `GGML_NATIVE=OFF` (never tune for the CI runner) with AVX, AVX2, FMA and F16C on (Haswell, 2013, and later). A processor without them cannot run the worker, so `hardware::recommend` returns no model with the reason `UnsupportedCpu` instead of Base (4, "Detection"; the UI says dictation is unavailable on this processor). Every arm64 runs it. A baseline-SSE build would run everywhere but several times slower on every machine; revisit with the Vulkan spike, which needs ggml's dynamic backends anyway.
- **Bindings are generated, not bundled.** `WHISPER_DONT_GENERATE_BINDINGS=1` was tried first and fails on Windows: the bindings shipped in whisper-rs-sys are laid out for a C `long` of 8 bytes, and the MSVC build stops on their layout assertions (`attempt to compute 12_usize - 16_usize`). bindgen runs at build time instead, which needs libclang: LLVM on Windows (`C:\Program Files\LLVM`, on GitHub's Windows images and on the lead's machine), clang on Linux, Xcode on macOS. This replaces the "bindgen is avoided" line of Consequences.
- **Silero VAD in the package**: `crates/acta-app/build.rs` checks `assets/voice/ggml-silero-v6.2.0.bin` against the pinned size and SHA-256 when the file is there and fails the build otherwise. The file is not in the repository and was not downloaded here (no model download in this step); until packaging puts it beside the executable, the worker runs without the VAD (its spec takes `vad: None`) and only the energy segmenter and Whisper's own no-speech threshold guard against invented text. Fetching it in the release workflow, with this check, is the release engineer's.
- **Worker protocol and test mode**: the worker's first request (`Init`, over the pipe) names the engine; `Fake` (a scripted engine) exists in the shipped executable so the end-to-end test drives the real binary. It produces only the text it is given and opens nothing.
- **Phrase context**: one whisper state per take with `no_context` off carries the take's previous text as the prompt; a new take makes a new state (no `initial_prompt` string is built).
- **Size (measured on Windows x64, release profile, thin LTO, stripped)**: `Acta.exe` 48,318,976 bytes at `main` 3cf3def, 51,211,776 bytes with whisper.cpp and the worker: **+2,892,800 bytes (2.76 MiB)**, under the 10 MB budget. macOS and Linux not measured yet (CI of the merge).
- **Worker lifetime**: the client replaces a worker that is within a tenth of its idle time (at most 15 s) of exiting, rather than writing to one that is leaving.
- **Not measured**: the time to write a 5 s phrase with Small on this machine's CPU (no model was downloaded in this step); it moves to the hand check of the last PLAN item.
- **Acta must start on a processor without AVX2; only dictation is unavailable there.** whisper.cpp's AVX2 code is reachable only from the worker (`voice_worker.rs` is the only caller of whisper-rs); the GUI never calls into ggml. CI proves the start: on the Windows job, Intel SDE emulates a Sandy Bridge processor (AVX, no AVX2) and runs `Acta.exe --voice-worker` with its input closed, which goes through the C runtime start, every static initialiser (ggml's included) and the start of `main`, and must exit with 0 (`scripts/ci/windows-sde-start.ps1`). SDE comes from the `petarpetrovt/setup-sde` action (pinned), which mirrors Intel's archive; using it accepts Intel's SDE licence for CI only, nothing of it ships. On such a processor the first-use dialog and Settings say dictation is unavailable (`hardware::Reason::UnsupportedCpu`); the UI step owns that copy.
- **Crash data**: the worker sets `WER_FAULT_REPORTING_FLAG_NOHEAP` on Windows, `RLIMIT_CORE` to 0 on every Unix, and `PR_SET_DUMPABLE` 0 on Linux. Windows error reports can still carry thread stacks, which may hold a few samples or words of the phrase being decoded, and a machine whose administrator configured WER `LocalDumps` with full dumps writes them whatever the process asks; neither is in Acta's control. Audio is never held on the stack in bulk (phrase buffers are on the heap).
- **The model file is never replaced under a running worker**: `take::Controller::release_engine` stops every take, ends the worker and waits for it; downloading over a model, "Download again" and "Delete model" call it first and touch the file only when it confirmed.
- **The fake engine exists only in debug builds** (`cfg(debug_assertions)`): the end-to-end tests run the debug executable; a release worker answers `EngineSpec::Fake` with a model error.
- **Licences**: whisper.cpp (MIT) and Silero VAD (MIT) notices are in `scripts/licenses/third-party`.
- **CI**: Linux runners install `cmake` and `libclang-dev` (`scripts/ci/linux-deps.sh`); Windows jobs set `LIBCLANG_PATH` to `C:\Program Files\LLVM\bin` (`scripts/ci/windows-libclang.ps1`); the Intel macOS release build on the Apple silicon runner sets `CMAKE_OSX_ARCHITECTURES=x86_64`. `cargo test` puts every build-script link folder on `PATH` and whisper-rs-sys adds over a hundred, past what `cmd.exe` accepts: tests that start a shell pass it `PATH` without them.

## Note (2026-11-22): steps 4 and 5 built
Built on `gpui-engineer/voice-ui`. Two points for section 7 (privacy) and the review:

- **Resampler buffers.** Capture resamples with rubato's FFT resampler (`acta-app/src/voice/capture.rs`). `Resampler::reset`, called at the end of each take, zeroes its overlap and scratch buffers, but not the FFT's own working buffers (the last chunk's spectrum), and nothing is zeroed when the resampler is dropped: those few milliseconds of audio are freed without zeroing. Memory only: they never reach a file, a log or a pipe. Every buffer Acta owns (the ring, the phrase buffers, the resampler's input and output scratch) is zeroed as section 7 asks.

A take never starts on a model while it is being downloaded or downloaded again, and downloading over the model a running take uses is refused (`voice.model.busy`).

## Amendment (2026-11-22): Vulkan spike
Spike in `spikes/whisper-vulkan/` (branch `integration-engineer/vulkan-spike`), run on Windows 11 x64: AMD Ryzen 7 9850X3D (8 cores, 8 threads used), NVIDIA GeForce RTX 4080 SUPER, Vulkan 1.4.357, driver 621.24. Model `ggml-tiny-q5_1.bin` (hash checked against section 4), greedy, English. Clips generated on the machine: 6.8 s of speech from the offline SAPI voice ("Alexandre wants the release notes ready by Friday...") and a 5.0 s 440 Hz tone. Five `full()` calls per run, median.

**A bug found on the way, fixed on this branch.** On Windows the `cmake` crate (0.1.58), with the default Visual Studio generator, sets `CMAKE_<LANG>_FLAGS_RELEASE` itself and strips every `/O` flag from it: whisper.cpp in `Acta.exe` is compiled without optimisation. `.cargo/config.toml` now sets `CMAKE_C_FLAGS_RELEASE` and `CMAKE_CXX_FLAGS_RELEASE` to `-O2 -DNDEBUG` (cl, gcc and clang accept it; the crate leaves a defined variable alone; elsewhere it replaces CMake's default `-O3 -DNDEBUG`). whisper-rs-sys does not rerun its build script when these change, so a cached target directory must have `whisper-rs-sys` cleaned (CI caches included). Linux and macOS were not affected (the crate does this only for MSVC without an explicit generator).

| Build (same machine, same clip) | 6.8 s speech | 5.0 s tone | Executable |
|---|---|---|---|
| CPU, as `main` builds it (no `/O2`) | 4,106 ms | 3,926 ms | 2,998,272 B |
| CPU, with the fix | 212 ms | 218 ms | 1,388,544 B |
| Vulkan build, GPU | 22 ms | 12 ms | 56,904,704 B |
| Vulkan build, loader missing (CPU) | 225 ms | 205 ms | same |

The text was identical in every mode ("Alex Sandroin, the release note ready by Friday and the build most pass before we ship." from Tiny; "(siren wailing)" for the tone). The first GPU run ever on the machine took 9.4 s (the driver compiling ggml's pipelines; later processes: 52 to 63 ms for their first run, then 21 ms). The fix makes the CPU 19 times faster and shrinks whisper.cpp's share of the executable by about 1.5 MB; the 2.76 MiB of the steps 1 to 3 amendment is to be measured again.

**Fallback without the loader works from one executable.** ggml-vulkan reaches Vulkan through Vulkan-Hpp's dynamic dispatcher except for three symbols it calls directly: `vkGetInstanceProcAddr`, `vkCmdCopyBuffer`, `vkGetPhysicalDeviceFeatures2`. The spike defines those three in Rust (`#[no_mangle]`), so the linker resolves them there and the executable does not import `vulkan-1.dll` (checked with `dumpbin /dependents`). The shim loads `vulkan-1.dll` from System32 only (`LOAD_LIBRARY_SEARCH_SYSTEM32`, never the install folder) on first use. Without it, it answers `vkEnumerateInstanceVersion` with 1.0; ggml throws "Vulkan 1.2 required" and catches it itself, the Vulkan backend is not registered and Whisper runs on the CPU at full speed (last row; simulated by asking the shim for a file name that does not exist, the same `LoadLibraryExW` failure). Option (b), ggml's dynamic backends, was not needed: whisper-rs-sys cannot build them (Context) and the shim gives the same result.
- ggml registers every compiled backend at first use whatever `use_gpu` says, and its scheduler offloads large operations to a registered GPU: with the loader present and `use_gpu(false)`, the Vulkan device was still used (two backends). A worker meant to run on the CPU must disable the shim (it then behaves as without the loader), so no GPU driver is loaded at all.
- On Linux the design is the same three symbols over `dlopen("libvulkan.so.1")`; without the shim, `-lvulkan` would stop the whole executable from starting where the loader is absent. Not built or run here.

**Size: this is what blocks it.** ggml-vulkan embeds its compiled shaders (every quantisation and matrix-core variant). The executable grows by **55.5 MB** over the optimised CPU build (56.9 MB against 1.4 MB), **16.4 MB** compressed (zip, deflate: 17,067,318 B against 671,788 B). Section 4's budget is 10 MB per platform. The shader set is chosen by ggml's CMake from what `glslc` supports and cannot be narrowed through whisper-rs-sys; trimming it needs an own `-sys` crate or a patch (Consequences).

**Build needs** (all free): `VULKAN_SDK` with the headers (`vulkan.hpp` included), the loader's import library and `glslc`. On Windows the LunarG SDK installer provides them and CI can run it silently or through a setup action; on Linux `libvulkan-dev` and `glslc` from the distribution. Neither was run on CI here. Locally the spike assembled the three pieces without installing anything (spike README). ggml-vulkan builds its shader generator as a nested CMake project whose compiler check fails beyond MAX_PATH: the target directory must stay short, or Ninja is used.

**Not verified**: a machine with the loader but no Vulkan 1.2 device (by the code, ggml throws and catches as above); a driver that crashes or hangs while the instance is created (the worker dies; the client would restart it with the GPU off); AMD and Intel GPUs; Linux; Small and Large turbo on the GPU (only Tiny was downloaded); the memory query for the GPU tier (DXGI, or `VkPhysicalDeviceMemoryProperties` through the shim's loader).

**Decision: not in v0.6.0.** The mechanism works and is small (about 80 lines), but it adds 55.5 MB installed and 16.4 MB to every download and full update, five times the budget, for a speed-up only the Large turbo tier needs: with the fix, Tiny on this CPU writes a 5 s phrase in about 0.2 s, and Small should stay within section 6's 2 s on a 4-core laptop (to be measured in the hand check). v0.6.0 ships the CPU fix. The Vulkan step waits for the user to choose among:
1. Vulkan in `Acta.exe` for everyone, with the shim: one executable, no ADR 0004 change, +16.4 MB per download.
2. A second executable, the Vulkan worker, built by the release workflow and not in the package: downloaded on the click that picks Large turbo on a GPU, like a model, from Acta's own GitHub release, its size and SHA-256 compiled into `Acta.exe` by the same workflow. It imports the loader normally and needs no shim; a start failure (no loader, no device, a crash) falls back to the CPU worker. The package is unchanged, but code is downloaded after installation, which relaxes the "embedded only" addendum and amends ADR 0004.
3. A trimmed shader set (an own `-sys` crate building ggml-vulkan with fewer variants), then 1 if it fits the budget. Unmeasured.
