# Acta design: record page parts

Part of the Acta design system. [DESIGN.md](../../DESIGN.md) is the index: direction, principles, the never-list and the review checklist. Section numbers are shared across all parts.

## 5. Components (continued): record page parts

States, the focus ring and the controls used here (buttons, inputs, rows, menus, dialog, notice, empty state) are in [components.md](components.md).

**Timeline entry**: a two-column block, gutter 20 + gap 12, then content.
- Gutter: the author mark, 20 x 20, top-aligned with the header line. **Human**: circle, `fill.selected`, initial in 12px weight 600 `text.primary` ("A" for Alexandre). **Claude Code**: square with `radius.xs`, no fill, 1px `border.strong`, Lucide `chevron-right` 12 in `text.secondary` (a prompt mark).
- Header (line 20): author name, then entry type, then time. Human name in `type.ui-strong`; "Claude Code" in `type.code` `text.primary`. Circle plus sans versus square plus mono is the at-a-glance distinction: shape and typeface, no colour, no badge. Type: icon 14 plus word in `type.small` `text.secondary`. Time: `type.small` `text.tertiary`, `tnum`, in the long form of 10.2 ("2 h ago", "Yesterday 18:42", "Tue 14:05", "12 Nov 2026"); tooltip gives the full local date and time.
- Body: rendered Markdown, 4 below the header.
- By type: **Progress** (`git-commit-horizontal`): plain. **Decision** (`signpost`): body and header sit in a 1px `border.default` box, `radius.lg`, padding 12 x 16, hanging 17 into the column gutter on each side so its author mark and text stay in the columns of the other entries, and the word "Decision" is `text.primary` weight 600; decisions are the entries people come back for, so they are the only ones with an outline. **Discussion** (`message-square`): plain.
- **System event** (status change, creation, moved): one line, no author mark, a status glyph 14 in the gutter, `type.small` `text.tertiary`: "Alexandre set status to Blocked - 2 h ago". Consecutive events within 5 minutes collapse into one line.
- States: hover reveals a ghost `ellipsis` button at the top right (also `Shift+F10` / context-menu key on the focused entry) with Edit, Copy as Markdown, Change type, Delete; focused: ring around the entry; editing: body becomes the multi-line editor in place; newly arrived from another process: `accent.subtle` background fading out (see 6.5).

**Current-state panel**: `bg.raised`, 1px `border.subtle`, `radius.lg`, padding 16. Label row: "Current state" in `type.label` `text.secondary`, right-aligned meta "Updated 2 h ago by Claude Code" in `type.small` `text.tertiary`. Body `type.reading`, intended to stay under about 6 lines; over 12 lines it clamps with a "Show all" ghost button. Empty: placeholder text "Where does this stand? One or two sentences." in `text.tertiary`.

**Note card**: `bg.raised`, 1px `border.subtle`, `radius.lg`, padding 12 x 16. Body `type.reading`, clamped to 6 lines when not focused. Meta row (`type.small` `text.tertiary`): time, and for filed notes "Filed as" plus a link to the topic or epic (id and title, `accent`), or "Dismissed"; "by Claude Code" when Claude Code filed it. Hover or focus reveals ghost icon buttons: Make topic (`corner-down-right`), Edit (`pencil`), Delete (`trash-2`); on a filed note, Back to inbox (`inbox`) instead of Make topic. Focused: focus ring. Filed: body in `text.secondary`.

**Properties block** (under the title of every record page; the model's own fields, shown as a page's typed properties). Rows of 28, two columns, no box and no dividers; 12 under the title, 24 above the next section. Label: `type.ui` `text.tertiary`, in a column exactly as wide as the longest label of the block in the current language (never a fixed width; capped at 40% of the column, beyond which a label truncates with a tooltip). Gap 16. Value: `type.ui` `text.primary`. A value that can be changed is a ghost control (padding 0 x 8, shifted left by 8 so its text aligns with plain values; hover `fill.hover`); a value that cannot is plain text. The block is one stop when stepping through a page with `Up` / `Down`; `Enter` goes inside, `Up` / `Down` move between rows, `Enter` acts on the value, `Esc` leaves. The direct keys (`S` status, `D` due date, `M` move) act on the page's record from anywhere on the page, unless the focused element has its own meaning for the key: the focused element always wins. `M` on a focused knowledge row moves that entry, not the topic; on a folder row it does nothing; in a text field it types.

| Page | Rows, in order |
|---|---|
| Topic | **Status**: the status indicator button. **Due**: the due date (below). **Epic**: the epic's name, a link; `M` or the row's menu moves the topic; "None" in `text.tertiary` for a topic outside any epic. **Folders**: the working folders row. **Id**: "T-42" in `type.code` `text.secondary`, the short id Claude Code uses; activating it copies it and the value reads "Copied" for 1.5 s. **Updated**: "2 h ago by Claude Code" (time rules of the timeline; tooltip with the full date). |
| Epic | **Progress**: "3 of 7 topics done" with a bar (120 x 4, `radius.xs`, track `fill.selected`, fill `text.secondary`): topics Done over all topics not Dropped. **Due**. **Folders**. **Id**: "E-7". **Updated**. |
| Project | **Progress** (same rule over the whole project). **Due**. **Folders**. **Updated**. |
| Document or memory | **Kind**: "Document" or "Memory" (menu: Change kind). **Level**: the owner, "Topic Embed the terminal", a link (`M` moves the entry). **Id**: "K-7". **Updated**: "2 h ago by Claude Code". |

There are no user-defined properties and no empty rows to hide: every row is a field the model has for every record of that kind, so the agent and the human always see the same set. The due date is the one optional value (added by the user's decision of 2026-11-21): its row is always shown, set or not, so the set of rows never changes.

**Due row** (topic, epic, project; one optional calendar date per record, day precision, no time, no recurrence; data.md 11, request 16). The value is a ghost control. Empty: "None" (`due.none`; French "Aucune", agreeing with *échéance*) in `text.tertiary`. Set: two runs 8 apart, never joined into one string: the absolute date in the `{date}` form of 10.2 ("15 Dec 2026", `text.primary`), then the relative phrase of 10.2.1, `type.ui`:

| Case (today is the local date, 10.2.1) | Relative phrase | Colour of the phrase |
|---|---|---|
| Before today, on an open record (**overdue**) | "Overdue by 3 days" (`due.overdue`) | `warning` |
| Today | "Today" (`due.today`) | `text.secondary` |
| Tomorrow | "Tomorrow" (`due.tomorrow`) | `text.secondary` |
| 2 or 3 days ahead (**due soon**, with today and tomorrow) | "In 3 days" (`due.in_days`) | `text.secondary` |
| 4 days ahead or later | "In 24 days" (`due.in_days`) | `text.tertiary` |
| Any date, on a closed record | none: the date alone, in `text.secondary` | |

**Open and closed for due dates.** A topic is open when Draft, Planned, Active or Blocked. An epic or a project is open while its Progress is below 100% or it has no topic at all. A closed record is never overdue, anywhere (page, table, tree, agent output): "Done" answers the date. Thresholds are in whole local days: overdue below 0, due soon 0 to 3, later 4 and more. The words carry the state, so the row reads in greyscale; `warning` is the colour of "needs you", the meaning Blocked already has (2.3). Measured on `bg.base`, dark / light: `warning` 6.96 / 5.87, `text.secondary` 7.50 / 7.26, `text.tertiary` 5.78 / 5.67.

Keys: `Enter` on the row, `D` from anywhere on the page, or a click opens the **due date picker** anchored to the value; `Delete` or `Backspace` on the focused row clears the date. An epic or a project shows its own date only, never one derived from its topics: the topic table's Overdue filter (below) answers "which topics are late", and a derived date would change under the reader each time a topic moved. There is no check that a topic's date falls before its epic's: dates are the human's plan, not constraints.

**Due date picker** (the one date control; opened from the Due row, from `D` on a focused tree or table row, and from the palette command "Set due date..."). A floating layer: `bg.overlay`, 1px `border.default`, `radius.lg`, `shadow.overlay`, padding 12, width 248. It opens 4 below its anchor (the Due value; on a tree or table row, the row's title), left edges aligned, and flips above when there is less room below. From the palette it anchors to the page's Due value, scrolling the least amount that shows it (the human asked, so 6.5 rule 2 is not broken); when the target is a row in a list rather than the open page, it anchors to that row. Top to bottom:

1. **Input**: the text input of 5, full width, 28. Starts empty and focused, placeholder "fri, in 3d, 15/12, 2026-12-15" (`due.picker.placeholder`). It parses on every keystroke with the grammar of 10.2.1, a pure function answered on the next frame.
2. 4, then the **preview line** (16, `type.small`): what `Enter` would set. Text that parses: the full date of 10.2.1 ("Friday 27 November 2026") in `text.primary`, then 8, the relative phrase coloured as in the Due row (`warning` for a past date). Text that does not parse: "Not a date. Try fri, in 3d, 15/12 or 2026-12-15." (`due.picker.invalid`) in `text.tertiary`; after `Enter` on it, the same words in `danger` with `triangle-alert` 14, and the input border `danger` (5, Text input, Invalid). A year outside 2000 to 2099: "Choose a date between 2000 and 2099." (`due.picker.range`), same two states. Empty input: the record's date in the same form, or "No due date" (`due.picker.none`) in `text.tertiary`.
3. 8, then the **month header** (28): month and year in `type.label` `text.primary` ("November 2026" / "Novembre 2026", 10.2.1), and at the right two compact ghost icon buttons 24, `chevron-left` and `chevron-right`, tooltips "Previous month" / "Next month" (`due.picker.prev`, `due.picker.next`) with their keys `PageUp` / `PageDown`.
4. 4, then the **weekday row** (16): the short weekdays of 10.2, Monday first in both languages ("Mon" to "Sun", "lun." to "dim."), `type.small` `text.tertiary`, centred on the columns.
5. 4, then the **grid**: 6 rows of 7 day cells, each 32 x 28, `radius.sm`, the day number `type.ui` with `tnum`, centred. Rest `text.primary`; days of the adjacent months `text.tertiary`. Hover `fill.hover`. **Today**: a 1px `border.strong` outline inside the cell, a shape that reads in greyscale (3.53 / 3.55 against `bg.overlay`). **Selected** (the date `Enter` would set: the parsed input, else the record's date): `fill.selected`, `type.ui-strong`, `text.primary` (8.08 / 11.37, 2.2). **Keyboard cursor**: the focus ring of 5. No colour on any cell; the accent is the focus ring only.
6. 8, then the **footer** (28), only when the record has a date: ghost button "Clear" (`common.clear`) at the left, a `Tab` stop. No chord clears from the input, because `Ctrl+Backspace`, `Alt+Backspace` and `Cmd+Backspace` already delete words or lines there.

Size: 248 x 300 (12 + 28 + 4 + 16 + 8 + 28 + 4 + 16 + 4 + 168 + 12), 336 with the footer; it fits above or below any anchor in the 880 x 560 minimum window.

Keyboard (focus stays in the picker until it closes, then returns to the anchor, 6.2):
- **Input**: typing parses. `Enter` sets the parsed date and closes; on an empty input it sets the selected day if it differs from the record's, else closes; on text that does not parse it shows the invalid state and sets nothing. `Down` moves the keyboard cursor into the grid, on the selected day, else today.
- **Grid**: `Left` / `Right` a day, `Up` / `Down` a week, `Up` from the first row back to the input; `Home` / `End` Monday / Sunday of the row; `PageUp` / `PageDown` a month, `Shift+PageUp` / `Shift+PageDown` a year, keeping the day number (clamped to the month's last day); `T` today; `Enter` or `Space` sets the cursor's day and closes. A cursor moved into another month turns the page to it.
- **Clearing**: `Delete` or `Backspace` in the grid, or the Clear button, clears the date and closes (when there is one). Outside the picker, `Delete` on the focused Due row and the palette command "Clear due date" do the same.
- **Anywhere in the picker**: `Tab` / `Shift+Tab` cycle input, grid, Clear; `Esc` closes and changes nothing.
- **Pointer**: a click on a day sets it and closes; the chevrons turn the month; a click outside closes and changes nothing.

**Writes.** Set, change and clear are optimistic, one `Mod+Z` step each, with no toast (the value visibly changes), and add a system event to the timeline (request 10): "Alexandre set the due date to 15 Dec 2026" (`event.due_set`), "Claude Code cleared the due date" (`event.due_cleared`); consecutive changes within 5 minutes collapse into the last one, as other events do. A write from Claude Code while the picker is open never changes what the human typed (6.5, rule 4): the remote value appears in the row behind, and a date the human then sets wins and is undoable as any edit.

**Topic table** (the collection on epic and project pages; the last section, under Knowledge). A toolbar row (28): the filter as a segmented control, Open / All / Closed (default Open), the count in `type.small` `text.tertiary` ("7 topics"), and at the right a ghost `plus` button, "New topic" (`Mod+T`). A header row (28, `type.small` `text.tertiary`, 1px `border.subtle` under it): Status (24, no label), Title (fills), Due (88, right-aligned, only while a topic of the page has a due date, below), Entries (56, right-aligned), Updated (72, right-aligned, compact form of 10.2). Rows of 32, padding 0 x 8, `radius.sm`: status glyph 14, title `type.ui` `text.primary` truncated, the unread dot after the title, entry count and updated time in `type.small` `text.tertiary` with `tnum`. No lines between rows. Hover `fill.hover`; keyboard focus ring; the same keys as the tree (`Enter` open, `Mod+Enter` new tab, `S` status, `D` due date, `E` rename, `Alt+Up` / `Alt+Down` reorder, `Delete`). Closed topics render as in the tree (glyph and title `text.tertiary`, 2.3).
- **Due column** (2026-11-21). It exists, with the two filter segments below, only while at least one topic the page lists, open or closed, has a due date: a person who never sets a date never sees either. The cell is the compact due form of 10.2.1, `type.small` with `tnum`, right-aligned in a 72 text box (the widest compact form, as for Updated). An overdue open topic adds `clock-alert` 12, 4 before the text, and draws icon and text in `warning`: icon and colour together, so it reads in greyscale. Due soon (today to 3 days ahead) is `text.secondary`; later dates `text.tertiary` (`text.secondary` on a selected row, 2.2); a closed topic's date is `text.tertiary` with no icon, whatever it is. Tooltip: the sentence form of 10.2.1 ("Overdue by 3 days, due 18 Nov 2026"). No date: an empty cell. Measured, `warning` on `bg.base`, on `fill.hover` and on `fill.selected` over it: 6.96 / 5.96 / 5.53 dark, 5.87 / 5.28 / 5.00 light.
- **Due filters.** With the Due column the filter reads Open / Overdue / Next 7 days / All / Closed (`table.filter.overdue`, `table.filter.week`). Overdue: open topics due before today. Next 7 days: open topics due before today plus 7, overdue included, because the question is "what must be done this week". A rolling seven days, not the calendar week, so that on a Sunday it still looks ahead. Both list by due date, earliest first, until a header is activated; under 10.3 the control becomes a dropdown when it does not fit. If the last date is cleared while one of them is selected, the filter falls back to Open. The count follows the filter ("2 topics").
- **Sort by Due**: ascending puts the earliest date first; topics with no date come last in both directions; equal dates keep the tree's order.
- Default order is the tree's order, the one the human arranged. Activating a column header sorts by it (`chevron-up` / `chevron-down` 12 after the label) and a ghost "Reset order" appears in the toolbar; while sorted, reordering by drag or key is off.
- On a project page the table is grouped by epic: group rows of 28 (`type.label`, the epic's name as a link, "3 of 7 done" in `type.small` `text.tertiary` at the right), topics outside any epic first under "No epic". `Enter` on a group row folds it.
- Under 520 of column width the Entries column is dropped; Due stays, since it is the column the Overdue filter is about. Empty: the existing empty states ("No topics yet. ..." with "New topic").
- It is a table and only a table. A board was considered and left out (Direction).

**Overview section** (2026-11-21, the user's request for "a few reference points that say where we stand and help move forward"; data.md 11 request 17). It answers one question, **what needs me**, and only when something does. It is not a dashboard: no tiles, no cards, no charts, no totals that change every day without meaning anything. The user's constraint is the rule of this section: every line earns the attention it takes, and a calm project shows one quiet line.

*What is shown, and why each is kept.* Four **attention lines**, each present only when its count is above zero, in this fixed order, so at most four lines are ever on screen:

| Line (EN) | Counts | Action it leads to | Why it would be missed if removed |
|---|---|---|---|
| `circle-pause` "2 blocked topics" | Open topics whose status is Blocked. | Open the list, answer what each is waiting on. | Blocked is the one status that means "waiting on the human" (2.3), and Claude Code parks work there. The tree shows each glyph only inside unfolded epics; nothing else counts them across the project. |
| `clock-alert` "1 overdue topic" | Open topics whose due date is before today (10.2.1). Topics only, so the count equals the table's Overdue filter. | Open the list; finish, re-date or drop. | A date the human set has passed. The table's Overdue segment answers it only for someone who thinks to click it, and the tree never rolls due marks up into folded epics (4.2.1). |
| `circle-dot` "3 active topics with no activity for 7 days" | Topics whose status is Active and whose last activity (the newest entry of any kind, system events included, else the topic's creation) is on a local day at least 7 days before today. | Open the list; log where each stands, or set it to Planned, Blocked or Done. | Nothing else in Acta can show it: the tree keeps the accent Active glyph on a topic nobody has touched for a month, so the most reassuring signal on screen is the one that is wrong. It is usually a session that ended without a log, exactly what Claude Code needs repaired before it resumes. |
| `inbox` "6 notes in the inbox, the oldest for 12 days" | Open notes of the project, shown only when the oldest of them was captured at least 7 local days ago. | Open the inbox and file them (or `/acta:triage`). | The tree's Inbox count says how many, never how long. A fresh inbox is normal and stays silent here; an old one means ideas are being lost. |

When none applies, the section is its header row only, with "Nothing needs attention." beside the label: one calm line, no zeros, no "all clear" figures.

**Behind "More"** (one click, never on screen by default), for the reader who asks "where do we stand overall". Each block appears only when it has something to say:

| Block | Content | Why it would be missed if removed |
|---|---|---|
| **Last 7 days** | One line of up to three links, the non-zero ones only: "4 topics done", "2 decisions", "3 new topics". If all three are zero: "Nothing done, decided or opened in the last 7 days. Last activity {when}." | It is the only place that gathers the decisions logged across topics, which is how the human reviews what Claude Code decided while they were away. Done beside new says whether the open work is shrinking or growing. |
| **Epics** | One row per epic that is not complete and has a topic not Dropped, in stored order, "No epic" first when such topics exist: name (link), the progress bar of the Properties block, "3 of 7" in `type.small` `text.tertiary` `tnum`, and the epic's own due date in the compact form when it has one (the Due column's rules: `clock-alert` and `warning` when overdue). At most 8 rows, then "4 more epics" (opens the project's topic table); complete epics are one trailing line, "2 complete epics", in `text.tertiary`, not a control. | Where the project stands epic by epic without opening each one; the project's Progress property is one number for the whole. |
| **Knowledge** | "5 memories not updated for 90 days", only when above zero. Memories only: a document can be old and still true, but memories are what Claude Code reads first in every session (ADR 0005), so a stale one steers it wrong. | Nothing else ages memories; the knowledge list orders by level and recency, so the oldest sit unseen at the bottom. |

*Considered and left out, by decision:* the share of work by human and Claude Code (no action follows from it; the author marks already show who wrote what); session time (no presence data, request 2, and time spent is effort, not progress); weekly charts, sparklines, burn-down and velocity (at a few topics a week they are noise, and no reading of them changes what to do next; the Last 7 days line says the same in words); a project-wide percentage (already the Progress property); counts of entries or knowledge entries (volume is not progress); open questions past their date (no such record yet; if that spec lands it adds one attention line of the same form, and the maximum becomes five, never more); a cross-project overview (one project is worked at a time; the tree and the palette reach the others).

*Where it lives.*
- **Project page**: the first section, between the Properties block and the description (layout.md 4.2). Present while the project has at least one topic; absent when it has none, where the project's empty state (8.5) says what to do. "More" starts collapsed; its state is remembered per project (4.7, record id only).
- **Epic page**: a mini version, **collapsed by default**, present only when at least one of the first three attention lines applies to the epic's topics (the inbox and knowledge are project-wide). Collapsed, it is its header row: `chevron-right` 14, "Needs attention" in `type.label` `text.secondary`, then 8 and the number of lines that apply in `type.small` `text.tertiary` ("2"). Expanded (`chevron-down`), it shows those lines. It has no "More": the epic's Properties block already holds its progress and date. Expanded or collapsed is remembered per epic (4.7, record id only).
- **Nowhere else**: not in the tree, the status bar, the titlebar, a topic page or a view of its own. A dashboard view was considered and refused (Direction: no dashboards made of cards); the project page is where a person already goes to see a project.

*Geometry.* Header row 28: "Overview" in `type.label` `text.secondary`; when nothing applies, 8 after it, "Nothing needs attention." in `type.small` `text.tertiary`; at the right a compact ghost button (24), "More" / "Less" with `chevron-down` / `chevron-up` 14 after the label, sized to its label (10.3). Under the header, 4, then the attention lines: rows of 32, padding 0 x 8, `radius.sm`, hanging 8 into the column gutter as list rows do, so the glyph sits on the column's edge; glyph 14 centred in a 16 slot, 8, then the sentence in `type.ui` `text.primary`, its numbers with `tnum`; nothing at the right. Glyph colours: `circle-pause` and `clock-alert` in `warning`, a real problem, the colour they have everywhere else (2.3, the Due column); `circle-dot` and `inbox` in `text.secondary`, a prompt rather than a fault (the stalled glyph is the Active shape without the accent: the topic is active in name only). No other colour; the Overview spends no accent at rest. "More" expanded: 16 below the last attention line (or the header), each block opened by its label ("Last 7 days", "Epics", "Knowledge") in `type.small` `text.tertiary` on a 16 line, 4 above its content, blocks 16 apart. The Last 7 days links are inline ghost controls of 28 separated by 8 of space (the `·` of 8 in the wireframes). Epic rows are 28, name in `type.ui` truncated with the title tooltip, then fixed right columns so the bars align: bar 120 x 4 (`radius.xs`, track `fill.selected`, fill `text.secondary`, as in the Properties block), 12, "3 of 7" in a 56 column right-aligned, and the due cell in an 88 column right-aligned, present only when an epic of the list has a date. Under 520 of column width the due column drops first, then the bar shortens to 64. Height at rest: 28 when nothing applies, at most 28 + 4 + 4 x 32 = 160.

*Measured* (WCAG 2.x from the token hex values, the renderer's 8-bit blend; dark / light): sentence `text.primary` on `bg.base` 12.55 / 12.85, on `fill.hover` over it 10.75 / 11.56; `warning` glyph on `bg.base` 6.96 / 5.87, on `fill.hover` 5.99 / 5.27 (3.0 for glyphs); `text.secondary` glyph 7.50 / 7.26, on `fill.hover` 6.45 / 6.52; header note, block labels and figures in `text.tertiary` on `bg.base` 5.78 / 5.67 (never on a hovered or selected row, 2.2); progress fill `text.secondary` against its `fill.selected` track 5.95 / 6.18 (graphic, 3.0), the track itself 1.26 / 1.17 against the page, which is decoration because "3 of 7" carries the value; filter chip label `text.primary` on `fill.selected` over `bg.base` 9.93 / 10.91. Every line reads in greyscale: glyph shape plus words.

*States.* Every attention line, Last 7 days link, epic row, "4 more epics" and the Knowledge line is a ghost control: hover `fill.hover`, pressed `fill.pressed`, keyboard focus ring; activating it opens the list behind its number (below). There is no disabled state: a line with nothing behind it is not drawn. Counts follow the model live, another process included, on the next frame after the recount. A line appearing or disappearing never moves focus or the viewport (6.5): while the reader is below the section, the page stays anchored on its first visible row, as for any remote change. No loading state: the section is computed with the page's other queries inside the 50 ms open budget (request 17); during a recount the previous values stay. Relative values (overdue, the 7 and 90 days, the inbox's age, the last 7 days) are whole local days (10.2.1) and are recomputed at local midnight and on resume, with the due marks (6.3). "The last 7 days" is today and the six local days before it.

*Click-through.* Every number opens exactly the list it counts; the count and the list come from the same store query, so they can never disagree:

| From | Opens |
|---|---|
| Blocked | The page's topic table (project or epic) with the chip "Blocked" |
| Overdue | The topic table with its existing Overdue segment selected |
| No activity | The topic table with the chip "No activity for 7 days", oldest activity first |
| Inbox | The inbox page, Open filter |
| Topics done / Decisions / New topics | The topic table with the chip "Done in the last 7 days" / "Decided in the last 7 days" / "Created in the last 7 days" |
| An epic row; "4 more epics" | That epic's page; the project's topic table |
| Memories not updated | The knowledge base page, Kind: Memories, with the chip "Not updated for 90 days", oldest first |

Opening a table from the Overview scrolls the page to it (the human asked, so 6.5 rule 2 is not broken) and puts keyboard focus on its first row.

**Filter chip** (the one new control; on the topic table and the knowledge base page, set only from the Overview or the palette). On the topic table it takes the place of the segmented control while it is set; on the knowledge page it follows the dropdowns. Height 24, `fill.selected`, `radius.sm`, padding 0 4 0 8, label `type.ui` `text.primary`, then a compact ghost icon button `x` 16 with the tooltip "Clear filter". The count beside it follows the filter ("3 topics"). The `x`, `Backspace` on the focused chip, or `Esc` with focus in the list clears it and brings back the segmented control at Open. Column sorting still works under a chip. The chip is not saved (4.7): reopening the page shows its default list. Why a chip and not more segments: six filters of this kind would turn the table's segmented control into a dropdown at every width; they are reached from a number or a command, not browsed.

*Keyboard.* The Overview is one stop when stepping through the page with `Up` / `Down`, like the Properties block: `Enter` goes inside, `Up` / `Down` move between its controls in reading order ("More" last on the header row), `Enter` activates, `Esc` leaves. On an epic page, `Enter` on the header expands or collapses it, `Right` expands and `Left` collapses. Palette commands, acting on the active page's project, or on its epic when the page is an epic: "Show blocked topics", "Show topics with no activity", "Show topics done in the last 7 days", "Show topics decided in the last 7 days", "Show topics created in the last 7 days", "Show memories not updated for 90 days", "Overview: Show more" / "Overview: Show less". Overdue keeps the table's own segment; the inbox keeps "Go to inbox".
