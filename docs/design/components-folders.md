# Acta design: working folders

Part of the Acta design system. [DESIGN.md](../../DESIGN.md) is the index: direction, principles, the never-list and the review checklist. Section numbers are shared across all parts.

## 5. Components (continued): working folders

States, the focus ring and the controls used here (buttons, inputs, rows, menus, segmented control, checkbox, dialog, notice, empty state) are in [components.md](components.md).

**Working folders** (project, epic and topic pages; ADR 0008 as amended by ADR 0011; wireframes in 8.11). The folders Claude Code works in. Each level has its own ordered list of folders, each with a **name** and an **icon**. A page **sees** its own folders, then its epic's, then its project's (an epic: its own, then its project's): inheritance is unconditional, there is no switch. Of the folders a page sees, exactly one is **active**: Claude Code starts there. The others are **additional**: Claude Code may also read and edit them. The active folder is chosen per page and may be an inherited one; until the user chooses, it is the page's first own folder, or, with none, the active folder of the page above. The surface is one row at rest, because folders are set once and switched now and then; it unfolds in place into the list, like a memory.

- **Folder row** (height 28, `radius.sm`, gap 8; it is the value of the Folders property in the properties block of a topic, epic or project page, so it sits at the head of the page under the title; when unfolded its list opens under that row, pushing the properties below it down). In order: the disclosure chevron 16 (`chevron-right` / `chevron-down`); the **switcher** (below), which shows the active folder's icon 16 and its name in `type.ui` `text.primary`; with a gap of 12 the git state of the active folder (below); with a gap of 12 the count of other folders the page sees ("+3", `type.small` `text.tertiary`, `tnum`, absent at zero); with a gap of 12 the origin of the active folder when it is not the page's own, in `type.small` `text.tertiary`: "from epic Terminal" or "from project Acta", the name a link in the breadcrumb style to that page; then the state (the not-found words and their button). The order is fixed, so the origin is shown in every state. Only the folder name truncates (at the end, with `…`), then the origin's page name at 24 characters; the path is not on the folded row: it is the switcher's tooltip and the list's second line. When the column is under 520, the switcher and the count stay on the first line and the rest (git state, origin, state) moves to a second line aligned with the switcher's icon; the row is then 52, as a knowledge row is. The count therefore follows the switcher directly in both forms; on one line the git state sits between them. Hover `fill.hover` on the row outside the switcher; keyboard focus ring; a click on the chevron or the row, `Enter` or `Right` unfolds; the unfolded state is remembered per view.
- **Switcher** (the compact folder switcher; the same control in the folder row and in the terminal header, 4.5). A ghost button 24 high, padding 0 x 4, `radius.sm`: icon 16, name, then `chevron-down` 12 in `text.tertiary`. Tooltip: the full path of the active folder. A click, `Space` or `Alt+Down` opens a dropdown menu (5, Context menu) anchored under it, listing every folder the page sees in list order, grouped by origin under non-interactive group labels in `type.small` `text.tertiary` ("This topic", "From epic Terminal", "From project Acta"; a group without folders is absent). Each item: the folder's icon, its name, and in the shortcut slot the word "Active" on the active one. Choosing an item makes it active for this page at once (one undoable write) and closes the menu; choosing the active one does nothing. A folder that was not found is listed with `folder-x` and "Not found" in the shortcut slot and cannot be chosen (`text.disabled`). After a separator, "Edit folders..." unfolds the list with the cursor on the active row, and "Add folder..." opens the picker. Type-ahead selects by name. With a single folder the switcher is still a button (its menu has that one folder and the two actions), so the control never changes shape.
- **Git state** (for a folder in a git repository; ADR 0011 2). `git-branch` 12 in `text.tertiary` and the branch name in `type.small` `text.tertiary` (a detached head reads "detached at a1b2c3d", the short commit in `type.code`), then, when the working tree has changes, " · 3 changed" in the same style (`tnum`). Nothing for a folder outside git, for a git state not yet known, or when `git` is not installed: the line is absent, never "Checking...", because it is a hint and blocks nothing. A folder with an automatic commit mode adds `git-commit-horizontal` 12 in `text.tertiary` after the branch, with the tooltip "Claude Code commits automatically here" (or "Claude Code commits and pushes automatically here"); the words are in the tooltip and in the folder settings, so the mark is never the only carrier. Computed off the UI thread when the page opens and when the window regains focus; until it arrives the row renders without it, so nothing flickers.
- **Unfolded**: the row becomes a header (chevron, the switcher, then "Working folders" in `type.label` `text.secondary`, then the count of folders the page sees in `type.small` `text.tertiary`), and the list follows, inset 24 so its icons sit under the switcher's icon. In order: the group line "This topic" (or "This epic", "This project") and the page's own folders; the group line "From epic Terminal" and that level's own folders; the group line "From project Acta" and that level's own folders; a ghost button with `plus` 16, "Add folder..."; and one line in `type.small` `text.tertiary`: "Claude Code starts in the active folder and may also read and edit the others." A group without folders is absent, except the page's own group, which then reads "No folders of its own." in `type.small` `text.tertiary` under its group line, so it is clear where "Add folder..." puts one. Group lines are `type.small` `text.tertiary`, as in the knowledge section. A folder present at two levels is listed once, in the nearest level's group.
- **Folder list row** (two lines, height 52, padding 6 x 8, `radius.sm`; the second line inset to the name). First line, gap 8: the **active mark** slot 16 (`circle-dot` 16 in `accent` on the active folder; on any other row `circle` 16 in `text.tertiary`, shown on hover and keyboard focus only; a click on it makes that folder active), the folder's icon 16 in `text.secondary`, the name in `type.ui` (`text.primary` on the active row, `text.secondary` otherwise), the git state, and in the trailing slot the word "Active" in `type.small` `text.tertiary` on the active row. Second line: the path in `type.code` `text.tertiary`, middle-truncated (Path display, below). The active mark is never colour alone: shape (`circle-dot` against `circle`) and the word "Active" carry it. Hover `fill.hover` and a ghost `ellipsis` button (24); keyboard focus ring; dragging as a tree row (2px `accent` insertion line), within the page's own folders only. Order is the order of the switcher and of `--add-dir`; it no longer decides which folder is active. Keys are in 6.1.
- **Row menu, own folder**: "Set as active here", "Folder settings...", Show in Explorer (Reveal in Finder / Show in file manager), Copy path, Move up, Move down, "Choose another folder...", then after a separator "Remove from this topic" (or epic, or project). Remove is not styled as destructive: it detaches the folder, changes nothing on disk except taking out the Claude Code settings Acta wrote there (ADR 0011 3), and shows the toast "embed-terminal removed from this topic. Undo" (toasts name a folder by its name). Undo puts those settings back. Removing the active folder makes the default rule apply again; the switcher shows the result.
- **Row menu, inherited folder**: "Set as active here", Show in Explorer, Copy path, "Edit in epic Terminal". An inherited folder's name, icon, position and commit mode are edited at its own level; making it active is this page's choice and is allowed here.
- **Folder settings** (own folder only; "Folder settings..." or `F2`). The row unfolds in place, like a memory, into a small form inset to the name, 12 below the row, one control per line with an 8 gap, saving on change (each change one undoable write); `Esc` or a click outside folds it back.
  - *Name*: text input, width 240, placeholder the last segment of the path ("embed-terminal"). Empty means that default, which follows a Locate. `Enter` saves and folds.
  - *Icon*: a row of thirteen 28 x 28 ghost icon toggle buttons: "Automatic" first (showing the icon detection gives; tooltip "Automatic: a branch for a git worktree, a git folder for a repository, a folder otherwise"), then `folder-open`, `folder-git-2`, `git-branch`, `code`, `book-open`, `package`, `server`, `globe`, `smartphone`, `database`, `flask-conical`, `palette`. Selected: `fill.selected` and 1px `border.strong`. Arrows move, `Space` selects. Each has a tooltip with its name (catalogue `folders.icon.*`). At 468 the row wraps to two lines of seven and six.
  - *Commits by Claude Code* (only for a folder in a git repository; otherwise absent). Label in `type.label` `text.secondary`, then a segmented control "Manual" / "Commit" / "Commit and push", and under it one line in `type.small` `text.tertiary` describing the selected segment: "Claude Code commits only when you ask." / "After each finished, tested change, Claude Code commits it." / "After each commit, Claude Code also pushes to the branch's upstream. Never forced; it stops and tells you if a push is rejected or needs a sign-in."
  - With Commit or Commit and push selected, two checkboxes: "Commit in my name, without Co-Authored-By Claude" (initially the Settings default, 5 Settings > Claude Code) and "Also on main" (the repository's default branch by name; absent when no default branch is known; off). Under them, in `type.small` `text.tertiary`: "Commits use your git identity: Alexandre." (`git config user.name` in that folder). When git has no user name, instead, with `triangle-alert` 14 in `warning`: "Git has no user name for this folder, so commits will fail. Acta does not set it."
  - Last, in `type.small` `text.tertiary`: "Acta writes these rules to .claude/settings.local.json in this folder, kept out of git." Replaced, when it applies, by: "This folder's .claude/settings.local.json is tracked by git, so Acta does not write it: Claude Code will ask before each commit."; or "Your own attribution setting in .claude/settings.local.json is kept." (the same for the sign-in variables); or, on macOS and Linux, "The repository's own local settings set attribution, and that setting wins."
  - Changing the mode of the folder a running session works in marks the terminal header (4.5), so the user can restart it with the new instruction; the permission rules apply to the running session at once.
- **Another checkout of the same repository** (ADR 0011 1). An inherited folder that is another checkout of the same git repository as the active folder gets, under its row, inset to the name, one line in `type.small` `text.secondary` with `info` 14: "Another checkout of the same repository as embed-terminal. Not passed to Claude Code here." It is still listed and can be made active (the rule then applies the other way round). This is how a topic in its own worktree does not also get the main checkout. A folder inside the active folder's checkout, or containing it, is passed as usual.
- **Nothing attached anywhere up the chain**: the row has no chevron and no switcher and reads, in `type.ui` `text.tertiary` after `folder-open` 16, "No working folder. The terminal will ask where to start.", with a ghost button "Set working folder..." at the right. `Enter` on the row opens the picker. In this one case the folder is attached to the project, whichever page the row is on, exactly as the terminal's prompt saves it; a topic or epic row then reads "from project Acta", which is how the user sees where it went.
- **Folder not found** (the path is not a folder on this computer: deleted, moved, an unplugged drive, or imported from another machine per ADR 0006). The folder's icon becomes `folder-x` in `warning`, its name drops to `text.secondary`, and the trailing slot reads "Not found on this computer" in `type.small` `text.secondary` followed by the one repair action, a ghost button "Locate..." that is always visible, not hover-only. Locate opens the picker and replaces the path in place, keeping position, owner, name, icon, commit mode and every page's active choice; because it repairs the folder itself, it is offered wherever the folder appears, inherited rows included. Locating an inherited folder repairs the record of the level that owns it, for every page that sees it, so the result says so in a toast: "acta located for epic Terminal and everything that inherits from it. Undo". Locating an own folder shows no toast; the row changes in place. On the folded row, a missing active folder, which stops a launch, shows `folder-x` in `warning` in the switcher, the name in `text.secondary`, then the words and the button; a missing additional folder, which does not, leaves the switcher untouched and adds, 8 after the count, a `folder-x` 14 in `warning` and "1 not found" in `type.small` `text.secondary` ("+3  1 not found"), with no button: unfolding shows which one. Icon shape and words carry the state; `warning` is never the only signal. Existence is checked off the UI thread when the page opens and when the window regains focus; until the answer arrives the row renders as found. A check still pending after 400 ms puts "Checking..." in the trailing slot in `type.small` `text.tertiary`, per 6.3; it blocks nothing.
- **Repairing the rest.** After a Locate, Acta compares the old and the new path, takes the part that changed as the old and new root, and looks for other folders, at any level of any project, that are not found, sit under the old root and exist under the new one. If there are any, a Notice at the top of the active page (`info` icon) offers the same change: "7 other folders under D:\work were not found either. Apply the same change to them?", the old root in `type.code`, with ghost actions "Apply to 7 folders" and "Dismiss". Applying is one undoable step and answers with the toast "7 folders located. Undo". The count includes only folders the change would actually resolve; with none, no notice.
- **Same folder on two topics** (allowed; also two epics). Under the folder's row, inset to the name, one line in `type.small` `text.secondary` with `info` 14: "Also attached to topic Scrollback. A session started in this folder outside Acta opens on epic Terminal and is told about both topics." For two epics: "Also attached to epic Notes. A session started in this folder outside Acta opens on project Acta and is told about both epics." The other owner's name is a link; with three or more, "Also attached to topics Scrollback, Links and 2 more." The level named is the nearest one the candidates share. It is a line, not a Notice, and not a warning: sessions opened from Acta's terminal are unaffected, since the page they are opened from names the topic.
- **Choosing a folder.** Every "..." action above opens the platform's native folder picker (single selection, titled "Choose a working folder"), starting in the parent of the active folder, or the home folder. Cancelling changes nothing. "Add folder..." appends to the page's own list; when it is the page's first own folder and the page has made no choice of its own, it becomes active by the default rule (the switcher shows it). "Set working folder..." (palette) adds the folder to the open page and makes it active there; the exception is the empty case above, where no level has a folder and the command attaches to the project. Choosing a folder already in the own list adds nothing and moves the keyboard cursor to its row; choosing one the page inherits adds it to the own list (it is then listed once, in the own group). There is no typed-path field and no confirmation; every change is undoable (6.4) and appears in place, unfolding the row if it was folded. Changes made by another process (`acta link`) follow 6.5.
- **Path display.** Paths are `type.code`: they are the machine's strings, and mono keeps `l`, `I`, `1`, `\` and `/` unambiguous. Stored in the normal form of ADR 0008 (absolute, canonical, links resolved, no trailing separator, upper-case drive letter) and shown exactly as stored, with the separators of the platform that wrote them and no trailing separator; a path imported from another platform keeps its foreign separators, which is part of why it reads as not found. The home folder is shortened to `~` on all three platforms (`~\dev\acta`, `~/dev/acta`). A path that does not fit is truncated in the middle with a single `…` (U+2026, never three dots, which read as a parent folder), by whole segments: the root (`~`, `C:`, `/`, `\\server\share`) and the last segment always stay, and as many trailing segments as fit are kept: `~\…\acta-wt\embed-terminal`. If that does not fit, the root goes (`…\embed-terminal`); if the last segment alone does not fit, it is cut at its end. The path slot is never narrower than 160. The full absolute path, without `~`, is part of the row's accessible name (after the folder's name), what "Copy path" copies, and the switcher's tooltip. Paths and names in rows are not selectable text. Two paths are the same folder when their stored forms are equal, ignoring case on Windows and macOS: the one rule, shared with the CLI and hook resolution, behind "already in the list", "listed once" and "Also attached to...". Names are labels only: two folders may share a name, and nothing identifies a folder by it.
- **Terminal launch.** Opening the terminal from a page starts Claude Code in that page's active folder, with every other folder the page sees passed along, except another checkout of the same repository (above). Two cases replace the terminal grid with a message set as an empty state at the top left of the pane (padding 12, sans, on the terminal's surface), focused, with ordinary keys since no shell exists yet:
  - *No folder anywhere up the chain.* Heading "Where should Claude Code start?"; sentence "Embed the terminal has no working folder, and neither has its epic or its project." (an epic: "and neither has its project"; a project: "Acta has no working folder yet."); a checkbox, checked, "Save as the working folder of project Acta"; under it in `type.small` `text.tertiary`, "If not saved, it is used until Acta quits."; then the primary button "Choose a folder...". The picker's result starts the session at once.
  - *The active folder was not found.* Heading "The working folder was not found"; sentence "Claude Code was not started. This is the active folder of topic Embed the terminal, and it is not on this computer:"; the full path in `type.code`, selectable, wrapping at separators; then "Locate folder..." (primary; the same repair as in the list, then the session starts), "Try again" (secondary; for a drive that was reconnected), and, when the page sees another folder that exists, under them the line "Or start in another folder:" in `type.small` `text.secondary` and the switcher (choosing makes that folder active for the page and starts the session there). Acta never starts the session in another folder on its own.
  - A missing *additional* folder does not stop the launch: it is left out, and a toast with `triangle-alert` in `warning` says "acta-docs was not found and was left out of this session. Locate". Like an error toast it stays until dismissed. Locate repairs the record; the running session is not touched, so the toast that follows reads "acta-docs located. Restart the terminal to include it." with the action "Restart terminal here".
  - While "Try again" is checking, both buttons are disabled; after 400 ms the line "Checking..." (`type.small` `text.tertiary`) appears under them until the answer arrives.
  - *The session is on something else.* One session per project stays, and navigating or switching folders never restarts or moves it. The terminal header names the session's page and folder and marks a mismatch; the rules, the header switcher and "Restart here" are in 4.5.
