# Acta design: working folders

Part of the Acta design system. [DESIGN.md](../../DESIGN.md) is the index: direction, principles, the never-list and the review checklist. Section numbers are shared across all parts.

## 5. Components (continued): working folders

States, the focus ring and the controls used here (buttons, inputs, rows, menus, dialog, notice, empty state) are in [components.md](components.md).

**Working folders** (project, epic and topic pages; ADR 0008; wireframes in 8.11). The folders Claude Code works in: the first is the **primary** folder, where a session starts; the others are **additional** folders it may also read and edit. Each level has its own ordered list. The **effective** folders of a page are its own if it has any, otherwise those of the nearest level above that has some. The surface is one row at rest, because folders are set once and read rarely; it unfolds in place into the list, like a memory.
- **Folder row** (height 28, `radius.sm`, gap 8; it is the value of the Folders row in the properties block of a topic, epic or project page, and when unfolded its list opens under that row, pushing the properties below it down): disclosure chevron 16 (`chevron-right` / `chevron-down`), `folder-open` 16 in `text.secondary`, the primary effective path in `type.code` `text.primary`, then with a gap of 12 the count of additional folders ("+2", `type.small` `text.tertiary`, `tnum`, absent at zero), then with a gap of 12 the origin label in `type.small` `text.tertiary`: "from epic Terminal" or "from project Acta", the name a link in the breadcrumb style to that page. No label means the folders are this page's own. The order of elements is fixed: chevron, icon, path, count, origin label, then state (the not-found words and their button), so the origin is shown in every state. Only the path truncates; the name in the label truncates at 24 characters. When the column is under 520, whatever follows the path (label, or the not-found words and their button) moves to a second line under it and the row is 52, as a knowledge row does; the same holds for list rows. Hover `fill.hover`; keyboard focus ring; a click, `Enter` or `Right` unfolds; the unfolded state is remembered per view.
- **Unfolded**: the row becomes a header ("Working folders" in `type.label` `text.secondary`, the count of effective folders in `type.small` `text.tertiary`), and the list follows, inset 24 so its icons sit under the header's label. In order: the page's own folders; the checkbox "Also include inherited folders" (only when the page has own folders and a level above has some; off by default, so a topic in its own worktree does not also get the main checkout); the inherited folders under a group line "From epic Terminal" (`type.small` `text.tertiary`, as in the knowledge section); a ghost button with `plus` 16, "Add folder..."; and one line in `type.small` `text.tertiary`: "Claude Code starts in the primary folder and may also read and edit the others."
- **Folder list row** (height 28, padding 0 x 8, `radius.sm`, gap 8): `folder-open` 16, the path in `type.code` (`text.primary` for the primary folder, `text.secondary` for additional ones), and in the trailing slot the word "Primary" in `type.small` `text.tertiary` on the first effective row only. Order is the whole meaning: first is primary, the rest are passed in list order. Hover `fill.hover` and a ghost `ellipsis` button (24); keyboard focus ring; dragging as a tree row (2px `accent` insertion line), within the own folders only. Keys are in 6.1. Row menu: Show in Explorer (Reveal in Finder / Show in file manager), Copy path, Make primary, Move up, Move down, Choose another folder..., then after a separator "Remove from this topic" (or epic, or project). Remove is not styled as destructive: it detaches the folder, changes nothing on disk, and shows the toast "embed-terminal removed from this topic. Undo" (toasts name a folder by its last segment, never the full path).
- **Inheritance, shown not explained.** A page without own folders unfolds to the group line and the inherited rows, which are read-only here (menu: Show in Explorer, Copy path, "Edit in epic Terminal"), then the ghost button "Set folder for this topic..." and the line "This topic uses the folders of epic Terminal. A folder set here replaces them for this topic only." Once the page has an own folder, the inherited ones stop applying and the checkbox appears, off: under it one line, "Not used here: 2 folders from epic Terminal." Checked, the line is replaced by the group and its rows, appended after the own folders as additional folders in their own order (the level above's primary is additional here); a folder present in both lists is shown once, in its own position. "Inherited" always means the effective folders of the level directly above, so an epic that itself includes its project's passes both on. The checkbox saves on toggle.
- **Nothing attached anywhere up the chain**: the row has no chevron and reads, in `type.ui` `text.tertiary` after the icon, "No working folder. The terminal will ask where to start.", with a ghost button "Set working folder..." at the right. `Enter` on the row opens the picker. In this one case the folder is attached to the project, whichever page the row is on, exactly as the terminal's prompt saves it; a topic or epic row then reads "from project Acta", which is how the user sees where it went.
- **Folder not found** (the path is not a folder on this computer: deleted, moved, an unplugged drive, or imported from another machine per ADR 0006). The icon becomes `folder-x` in `warning`, the path drops to `text.secondary`, and the trailing slot reads "Not found on this computer" in `type.small` `text.secondary` followed by the one repair action, a ghost button "Locate..." that is always visible, not hover-only. Locate opens the picker and replaces the path in place, keeping position, owner and primary rank; because it repairs the folder itself, it is offered wherever the folder appears, inherited rows included. An inherited folder keeps its origin: on the folded row the label stays between the count and the not-found words ("D:\work\acta  from epic Terminal  Not found on this computer  Locate..."), and in the list the group line names it. Locating an inherited folder repairs the record of the level that owns it, for every page that inherits it, so the result says so in a toast: "acta located for epic Terminal and everything that inherits from it. Undo". Locating an own folder shows no toast; the row changes in place. The folded row tells the two severities apart by position. A missing primary, which stops a launch, changes the leading icon to `folder-x` in `warning`, drops the path to `text.secondary` and shows the words and the button. A missing additional folder, which does not, leaves the leading icon, the path and their colours untouched and adds, 8 after the count, a `folder-x` 14 in `warning` and "1 not found" in `type.small` `text.secondary` ("+2  1 not found"), with no button: unfolding shows which one. Icon shape and words carry the state; `warning` is never the only signal. Nothing else is blocked: the topic, its knowledge and its timeline work as before, and the only other consequence is at terminal launch (below). Existence is checked off the UI thread when the page opens and when the window regains focus; until the answer arrives the row renders as found, so nothing flickers. A check still pending after 400 ms (a dead network path) puts "Checking..." in the trailing slot in `type.small` `text.tertiary`, per the loading rule of 6.3; it blocks nothing.
- **Repairing the rest.** After a Locate, Acta compares the old and the new path, takes the part that changed as the old and new root, and looks for other folders, at any level of any project, that are not found, sit under the old root and exist under the new one. If there are any, a Notice at the top of the active page (`info` icon) offers the same change: "7 other folders under D:\work were not found either. Apply the same change to them?", the old root in `type.code`, with ghost actions "Apply to 7 folders" and "Dismiss". Applying is one undoable step and answers with the toast "7 folders located. Undo". The count includes only folders the change would actually resolve, so the promise is exact; with none, no notice. This is what makes an import on another computer one Locate and one confirmation instead of one per folder.
- **Same folder on two topics** (allowed; also two epics). Under the folder's row, inset to the path, one line in `type.small` `text.secondary` with `info` 14: "Also attached to topic Scrollback. A session started in this folder outside Acta opens on epic Terminal and is told about both topics." For two epics: "Also attached to epic Notes. A session started in this folder outside Acta opens on project Acta and is told about both epics." The other owner's name is a link; with three or more, "Also attached to topics Scrollback, Links and 2 more." The level named is the nearest one the candidates share (their epic, otherwise the project). It is a line, not a Notice, and not a warning: sessions opened from Acta's terminal are unaffected, since the page they are opened from names the topic.
- **Choosing a folder.** Every "..." action above opens the platform's native folder picker (single selection, titled "Choose a working folder"), starting in the parent of the current primary effective folder, or the home folder. Cancelling changes nothing. "Add folder..." appends to the own list (the first own folder is primary); "Set working folder..." and "Set folder for this topic..." set the primary of the open page, replacing its current own primary and keeping its additional folders; the exception is the empty case above, where no level has a folder and the command attaches to the project. Choosing a folder already in the own list adds nothing and moves the keyboard cursor to its row. There is no typed-path field and no confirmation; every change is undoable (6.4) and appears in place, unfolding the row if it was folded. Changes made by another process (`acta link`) follow 6.5.
- **Path display.** Paths are `type.code`: they are the machine's strings, and mono keeps `l`, `I`, `1`, `\` and `/` unambiguous. Stored in the normal form of ADR 0008 (absolute, canonical, links resolved, no trailing separator, upper-case drive letter) and shown exactly as stored, with the separators of the platform that wrote them (`\` on Windows, `/` on macOS and Linux, UNC prefixes kept) and no trailing separator; a path imported from another platform keeps its foreign separators, which is part of why it reads as not found. The home folder is shortened to `~` on all three platforms (`~\dev\acta`, `~/dev/acta`). A path that does not fit is truncated in the middle with a single `…` (U+2026, never three dots, which read as a parent folder), by whole segments: the root (`~`, `C:`, `/`, `\\server\share`) and the last segment always stay, and as many trailing segments as fit are kept, since the end of a path is what tells two worktrees apart: `~\…\acta-wt\embed-terminal`. If that does not fit, the root goes (`…\embed-terminal`); if the last segment alone does not fit, it is cut at its end. The path slot is never narrower than 160. The full absolute path, without `~`, is the row's accessible name, what "Copy path" copies, and the path tooltip (see Tooltip) shown only when the row displays a shortened or truncated form. Paths in rows are not selectable text. Two paths are the same folder when their stored forms are equal, ignoring case on Windows and macOS: the one rule, shared with the CLI and hook resolution, behind "already in the list", "shown once" and "Also attached to...". The UI never compares the displayed strings.
- **Terminal launch.** Opening the terminal from a page starts Claude Code in that page's primary effective folder with the additional folders passed along. Two cases replace the terminal grid with a message set as an empty state at the top left of the pane (padding 12, sans, on the terminal's surface), focused, with ordinary keys since no shell exists yet:
  - *No folder anywhere up the chain.* Heading "Where should Claude Code start?"; sentence "Embed the terminal has no working folder, and neither has its epic or its project." (an epic: "and neither has its project"; a project: "Acta has no working folder yet."); a checkbox, checked, "Save as the working folder of project Acta"; under it in `type.small` `text.tertiary`, "If not saved, it is used until Acta quits."; then the primary button "Choose a folder...". The picker's result starts the session at once. This is asked once: saved, the project has a folder from then on; not saved, the choice holds for this project's terminal until Acta quits.
  - *The primary folder was not found.* Heading "The working folder was not found"; sentence "Claude Code was not started. This is the primary folder of epic Terminal, and it is not on this computer:"; the full path in `type.code`, selectable, wrapping at separators; then "Locate folder..." (primary; the same repair as in the list, then the session starts) and "Try again" (secondary; for a drive that was reconnected). Acta never starts the session in another folder on its own.
  - A missing *additional* folder does not stop the launch: it is left out, and a toast with `triangle-alert` in `warning` says "acta-docs was not found and was left out of this session. Locate". Like an error toast it stays until dismissed. Locate repairs the record; the running session started without the folder and is not touched, so the toast that follows reads "acta-docs located. Restart the terminal to include it." with the action "Restart terminal here".
  - While "Try again" is checking, both buttons are disabled; after 400 ms the line "Checking..." (`type.small` `text.tertiary`) appears under them until the answer arrives.
  - *The session is on something else.* One session per project stays, and navigating never restarts or moves it. The terminal's header always names what the session is on, and marks a mismatch with the active page; the rules and the "Restart terminal here" command are in 4.5.
