## Type and space

Rendered sizes on a record page today (captures and `crates/acta-app/src`): 24 / 600 title, 16 / 26 reading, 14 / 20 rows and property labels, 13 mono (ids, paths), 12 / 16 small and label. All sizes are on the scale (typography.md 3.2); every literal size in the code equals a role. The defects are of role, not of value:

| Defect | Where | Replacement |
|---|---|---|
| Section headers 12 under 14 property labels (finding 5) | `record_page.rs`, `kb_page.rs` section header rows; current-state label; Overview header; "Needs attention" | `type_scale::LABEL` → `type_scale::UI_STRONG` with `text_secondary` |
| Literal title instead of the role | `record_page.rs:1196`, `kb_page.rs:1767` (`px(24.)`, `px(30.)`, SEMIBOLD) | `type_scale::TITLE.el()` |
| Literal 12 / 600 | `ui.rs:400` (author mark initial) | `type_scale::LABEL` |
| Off-scale gap 6 | `shell.rs:4471` (usage meter, text to bar) | `px(4.)` |
| Mono at 13 among 12 small text | the new meta line's id | mono 12 / 16 (typography.md 3.2, the one exception) |

Space, at the three sizes:

- **880 wide** (captured at 896, the window's minimum): the terminal header's view tabs overlap the context label ("Agent browser" over "Claude · T-5 ..."; already being fixed). The decision box hangs 17 into the gutter and ends 8 from the window edge, closer than anything else on the page: it now hangs only with 24 to spare (components-records.md 5). The folders row's orphan second line is gone with finding 4. The title wraps to two lines, which is correct.
- **1280 to 1456 wide**: the page column is 560 in a 870 page area, the terminal 648: balanced. The Settings column keeps label and control 400 apart with the description in 12 px under the label; with one-line descriptions (finding 8) the rows become even at 44 to 52.
- **1920 wide**: the column stays 560 and centres; 360 of empty band on each side is right for reading. Nothing stretches; nothing to change. A reader who wants more uses Reading width: Wide.
- Vertical rhythm on the topic page: title 12 properties, 24 to the current-state panel, 32 between sections, as specified; the 7-row properties block was the only place where rhythm broke (seven equal rows read as a table); finding 1 fixes it.
- Settings: the gap between "Show plan usage" and the plugin paragraph is 8, between rows 16: the paragraph belongs to neither. Gone with finding 3.

## Timeline decision, consequences

- Filing a note as "Entry in {topic}" stays: the text already exists, written by the human as a note; filing only chooses where it goes. The same holds for "Also log it as a decision" on an answered question (pending, 10.4.6). Both are said in components-records.md 5. If the user wants these gone too, they are two menu items.
- "Claude Code changed this while you were editing." still applies, now only to an entry the human is editing (and to state and description, as before).
- Nothing changes in the store or the MCP (data.md request 21).
