# Acta design: knowledge components

Part of the Acta design system. [DESIGN.md](../../DESIGN.md) is the index: direction, principles, the never-list and the review checklist. Section numbers are shared across all parts.

## 5. Components (continued): knowledge

States, the focus ring and the controls used here (buttons, inputs, rows, menus, dialog, notice, empty state) are in [components.md](components.md).

**Knowledge section** (project, epic and topic pages; ADR 0007). Holds the two kinds of knowledge entry: **documents** (long-form reference) and **memories** (one durable fact in a few lines, mostly written by Claude Code, fully owned by the human). It is a section in the main column, not tabs and not a side column: tabs would hide either the timeline or the knowledge behind a click and add state to every topic; a side column would compete with the terminal for width and vanish at 880. A section keeps one scroll and one reading order, and costs 28px when empty.
- Header row (28): "Knowledge" in `type.label` `text.secondary`, count in `type.small` `text.tertiary`, and at the right a ghost `plus` button opening a two-item menu: New document (`Mod+Shift+D`), New memory (`Mod+Shift+M`).
- **Knowledge row** (height 32, padding 0 x 8, `radius.sm`, gap 8): kind icon 16 in `text.secondary` (`file-text` for a document, `pin` for a memory), title in `type.ui` `text.primary` (truncates, at most 40% of the row), 12 gap, summary in `type.ui` `text.secondary` (fills the rest, truncates), updated time in `type.small` `text.tertiary` `tnum`, in the compact form of 10.2, right-aligned in a fixed 72 column, its tooltip naming the last author ("Updated 2 h ago by Claude Code"). The author mark is not drawn in the row (clarity review 2026-11-22: the square Claude Code mark read as a button, and three trailing marks, dot, mark and time, made every row end in noise); it stays on the entry's page. Kind is the leading shape; no colour and no badges. When the column is under 520 the summary moves to a second line and the row is 52. Hover `fill.hover`; keyboard focus ring; one **signal slot** (16, always reserved, so nothing moves when it fills) left of the time column, holding at most one of two marks: the unread dot (6, `accent`) when another process created or changed the entry, which is how the human notices what Claude Code has just memorised, or else the **to-check mark** of a flagged entry (Memory quality, below). The dot wins while it is there: it goes once the entry is seen, and the mark then shows. The summary is always shown and never optional: it is what both readers pick by.
- **A document opens; a memory unfolds.** `Enter` or a click on a document row opens the document reading view. `Enter`, `Right` or a click on a memory row expands it in place: under the row, aligned with the title (left inset 32), the body in `type.reading`, then a meta row in `type.small` `text.tertiary` ("Written by Claude Code 2 h ago · edited by Alexandre 10 min ago") with ghost buttons Edit `E`, History `H`, Move `M`, Delete. `Left` or `Esc` folds it. One memory is expanded at a time. A memory longer than 12 lines clamps with "Open", which shows it in the reading view like a document; the tooltip then suggests making it a document ("Change kind" in the row menu converts either way, keeping history).
- **Editing a memory** happens in place: title as an inline title edit, summary as a text input ("One line: the fact, in short"), body in the multi-line editor, `Mod+Enter` saves, `Esc` cancels. The human's edit is what the agent reads from then on; the meta row says who wrote and who last edited.
- **Row menu** (`Shift+F10`, right click, or the `ellipsis` shown on hover): Open, Edit, Mark as still true `V`, Show history, Move to epic "Terminal", Move to project "Acta" (the two nearest other levels, one key press each), Move to..., Merge into... (memories only), Change kind, Save as file, Mark as no longer true, Delete. On a superseded or retired entry: Open, Make live again, Show history, Save as file, Delete (Memory quality, below). Dragging a row onto a tree row moves it too. Moving changes the owner only; the entry keeps its id and history, and the toast reads "Moved to project Acta. Undo".
- **Looking up, on a topic (and an epic)**: the page's own entries first, documents before memories, each by last update. Inherited entries follow in groups headed "From epic Terminal" and "From project Acta" (`type.small` `text.tertiary`, 8 above), nearest level first, collapsed by default into one ghost row "9 more from epic and project" whose expanded state is remembered per page. Inherited rows are the same entry, not a copy.
- **Looking down, on an epic or a project**: after the own entries, one ghost row "31 more in the topics of this epic" (or "in this project's epics and topics") opens the knowledge base page scoped to it. The section itself never lists descendants: a roll-up belongs in a view that can filter.
- More than 6 own entries: show 6, then a ghost row "Show all 14" (opens the knowledge base page scoped to this owner). Empty: one line in `text.tertiary`, "Nothing here yet. Documents and memories for this topic appear here.", with the inherited row still below.

**Knowledge base page** (a page; the destination for "what does this project know"). Reached from the Knowledge row of a project in the tree (`Mod+L` for the active page's project), from the roll-up rows above, and scoped to an epic from that epic's section. Top to bottom in the content column: title "Knowledge" (`type.title`) with the scope under it in `type.small` `text.tertiary` ("Acta · 12 documents, 43 memories"); a search input (28, full width, `search` icon, placeholder "Search knowledge", focused with `/`); a filter row of three compact secondary dropdown buttons, "Level: All", "Kind: All", "Author: All" (menus: All / Project / Epics / Topics; All / Documents / Memories; All / Alexandre / Claude Code), a non-default filter showing its value in `text.primary` weight 600, and a ghost "Clear" when any is set; after them, only when set from the Overview, the palette or the list's last row, one filter chip, "To check" or "Superseded and retired" (components-records.md 5, Filter chip; Memory quality, below); then the list.
- The list is grouped by owner, widest first: "Project Acta", "Epic Terminal", "Topic Embed the terminal" (group header 28: `type.small` `text.tertiary`, the name a link to the owner, count at the right). Rows are knowledge rows and behave identically (documents open, memories unfold, same menu). `J` / `K` cross groups; `Left` on a row jumps to its group header; `Enter` on a header folds the group.
- Searching is full text and instant (budget as the palette): groups with no match disappear, the summary is replaced by the matching excerpt with the matched words in `text.primary` weight 600, and the header line reads "7 results for "resize"". No results: "Nothing in this project mentions "resize"." Filters and search combine; both persist while the app runs and reset on restart.
- Only live entries are listed, searched and counted, here, in the Knowledge section of every page and in the palette (an exact id typed in the palette still opens a superseded or retired entry, so old references resolve). When the scope holds superseded or retired entries, the list ends, 8 under its last group, with one ghost row of 28, "4 superseded or retired" (`kb.inactive_row`, `type.small` `text.tertiary`, the pattern of the tree's "N closed" row); activating it sets the chip "Superseded and retired". No other place lists them.
- This view is also where the human reviews the agent's memory: "Author: Claude Code" plus "Kind: Memories" is one saved habit, so the palette has the command "Review memories written by Claude Code", which opens the page with those two filters, newest first, ungrouped.

**Document reading view** (a page, part of navigation history; the tree keeps the owner selected; a memory opened in full uses it unchanged). Top to bottom in the content column: title (`type.title`); summary (`type.reading` `text.secondary`); the properties block (Kind, Level, Id, Updated; see Properties block); a row of ghost buttons, Edit `E`, History `H`, and `ellipsis`: Go to heading, Save as file, Move, Delete; 24; a 1px `border.subtle` rule; 24; the body in the document setting of 3.3. No outline column: "Go to heading" (`Mod+Shift+O`) opens the palette scoped to this document's headings, with each section's size, which is the same outline the agent sees. `Space` / `Shift+Space` page, `Home` / `End` jump. The chosen heading scrolls to the top of the page (less 24). Save as file opens the platform's save dialog, in the home folder, named after the title (characters file systems refuse become `-`, at most 80, `.md`); it writes the body as stored, under the title as a first-level heading unless the body starts with one, and the toast says "Saved {name}. The file is not encrypted." (a file the user asked for, outside Acta, like an export). Move opens the palette as a picker of the project's other levels (the project, its epics, its topics with their path); the move is one undo step, toasted "Moved to epic Terminal." with Undo. All three are palette commands while a document or memory is open. Remote changes follow 6.5: the changed section gets the highlight, the viewport is anchored on the first visible block.

**Document editor**: the reading view switches in place, without moving the scroll position. Title becomes an inline title edit; summary becomes a text input with the placeholder "One line: what this is and when to read it" and a `tnum` counter in `type.small` `text.tertiary` ("64 / 140"); the body becomes a borderless raw-Markdown editor in `type.document` filling the column (no box: the page is the editor). A 44 bar is pinned to the bottom of the page area (`bg.base`, top border `border.subtle`): left, "Editing" plus the draft state in `type.small` `text.tertiary`; right, Cancel (ghost, `Esc`) and Save (primary, `Mod+Enter`). Save is disabled with the hint "A document needs a title and a summary." until both exist. Every save keeps the previous version, so there is no confirmation on save and none on cancel (the draft is kept). Markdown editing aids: `Enter` continues lists, `Tab` / `Shift+Tab` indent, `Mod+B` / `Mod+I` wrap the selection in `**` / `*` (inside an editor these win over the global shortcuts); nothing else, no toolbar.

**History** (documents and memories alike; for a memory, `H` opens it in the reading view first): `H` replaces the body with the history, same view, same header. A list of revisions, newest first (rows of 32: author mark, "Claude Code" or name, what changed in `text.secondary` ("Replaced section Storage", "Edited", "Created from file", and the state changes of Memory quality below), lines added and removed with `tnum` (absent on a revision that changed no text), time; on a Claude Code revision the name's tooltip says which session wrote it, one fact per line: "A Claude Code session on T-51" (`kb.session.on` / `kb.session.any`), "Branch feature/kb" (`kb.session.branch`, only off the default branch)); at most 6 rows visible, then scroll. Below the list, the selected revision rendered read-only, headed by a notice "Version from 17 Nov 2026, 14:05 by Claude Code" with a segmented control (Text / Changes) and a secondary button "Restore this version". Changes shows the raw Markdown with a 16 gutter: `+` in `success` for added lines, `-` in `danger` for removed lines whose text is `text.secondary`; no background tints. Restoring writes the old text as a new revision on top, so it is undoable, needs no dialog, and shows the toast "Restored the version from 17 Nov 2026, 14:05. Undo". `Esc` or `H` returns to reading.

**Memory quality** (ADR 0015; data.md 11 request 24; screens.md 8.31 to 8.33). Acta finds memories that may be wrong and says why; the human or Claude Code decides. Nothing here hides, rewrites or deletes an entry by itself. The rule for the human side is **one signal per row, one notice per entry, and nothing on screen when nothing is wrong**: a healthy knowledge base looks exactly as it did before this section.

*Reasons.* An entry is **to check** while at least one reason applies. Reasons are computed when the list or page is drawn, never stored; the store's arrive with the page's query, the git ones (file, branch) are read off the UI thread per folder, cached per `HEAD`, and arrive later without moving anything (the signal slot is reserved). The order, most telling first, is the agent's (`agent::kbq::Flag::rank`):

| Reason | Applies to | Text (tooltip line and notice line) | Cleared by |
|---|---|---|---|
| Open conflict pair | memories | "May contradict K-9" (`kb.reason.conflict`) | This replaces it, Keep both, an edit of either |
| File gone | entries with a file source | "kb.rs was deleted or moved" (`kb.reason.file_gone`; the file name only, the path is on the page) | Mark as still true |
| Branch gone | branch memories | "Branch feature/kb no longer exists" (`kb.reason.branch_gone`) | Mark as no longer true |
| File changed | entries with a file source | "kb.rs changed since it was checked" (`kb.reason.file_changed`) | Mark as still true |
| Branch merged | branch memories | "Branch feature/kb was merged" (`kb.reason.branch_merged`) | Mark as no longer true |
| Open duplicate pair | memories | "Possible duplicate of K-4" (`kb.reason.duplicate`) | Merge, Keep both |
| Folder removed | entries whose sources sat in one folder | "Its folder was removed from Acta" (`kb.reason.folder_removed`) | Mark as no longer true, restoring the folder |
| Topic closed | entries of a Done or Dropped topic | "Its topic is done" / "Its topic was dropped" (`kb.reason.topic_done`, `kb.reason.topic_dropped`) | Moving it up, reopening the topic |
| Old | memories only | "Not checked for 140 days" (`kb.reason.old`: the verified date is 90 days or more before today, `STALE_MEMORY_DAYS`) | Mark as still true, any content edit |

Ids in reasons are `K-n` as the meta line shows them; a reason never names a session, a score or a blob id. When a file reason applies to two or three sources, its line names the first and counts the others: "kb.rs and 1 more file changed since they were checked" (`kb.reason.file_changed_more`, `kb.reason.file_gone_more`).

*To-check mark* (knowledge rows everywhere: page sections, the knowledge base page, its search results). Lucide `flag` 14, centred in the signal slot, `text.secondary`, the same on a hovered or selected row (measured in 2.2: on `bg.base` 7.50 / 7.26, on `fill.hover` 6.45 / 6.52, on `fill.selected` 5.93 / 6.17; on `fill.selected` over `bg.sunken`, Knowledge in a sidebar, 6.41 / 5.81). No colour, no count, one mark whatever the number of reasons: the row says "look again", the tooltip says why. Tooltip (the tooltip of 5): the reasons, one per line, in the table's order. The time column and its tooltip are unchanged. Why `flag`: `circle-question-mark` is the questions glyph (Overview, components-questions.md 5), and `warning` is kept for what blocks work; a memory to check is a lead, not a fault.

*Mark as still true* (`kb.verify`; the verify act of ADR 0015, 1). `V` on a focused knowledge row, an unfolded memory or an open entry page; the row menu; the to-check notice; the palette. It records that the human vouches for the text as it is now: a revision "Marked as still true" with no text change, the verified date set to now, and file sources read again at `HEAD` and recorded. It clears Old, File changed and File gone; other reasons stay, and so does the mark while one does. Offered for every live entry, flagged or not (a fact checked today is worth recording). Optimistic, one `Mod+Z` step, no toast: the mark disappearing is the feedback. **A row never leaves under the reader**: with the "To check" chip set, a row with no reason left stays in place without its mark until the chip, the page or the search changes, so `V`, `J`, `V`, `J` walks the list.

*Mark as no longer true* (`kb.retire`; retire). Row menu, the to-check notice when nothing else clears its reasons, the palette; no key, because it takes the entry out of what Claude Code reads. No reason is asked of the human (the store accepts none; the agent gives one). The entry leaves the live list, often away from the reader's eyes, so it toasts "Marked as no longer true." with Undo (`kb.retired_toast.*`). Retire is not delete: Delete stays in the menu, separate, and goes to the trash as before.

*Notice.* An entry shows **one** notice (5, Notice; never more than one per view) above its body: on the entry page between the properties block (with its meta, provenance and presence lines) and the action row, 16 above and 12 below; in an unfolded memory between the row and the body, inset 32 like the body. The first row of this table that applies wins:

| Entry | Icon 16 | Message (`type.ui` `text.primary` on `bg.raised`: 11.34 / 13.40) | Ghost actions, right-aligned |
|---|---|---|---|
| Superseded | `info` `text.secondary` | "Superseded by {title} on {date}." (`kb.notice.superseded.*`); `{title}` is the successor's title as a link (`accent` on `bg.raised`: 6.13 / 5.92) that opens it, tooltip its id | Make live again |
| Retired | `info` `text.secondary` | "Retired by {author} on {date}." (`kb.notice.retired.*`), then, when there is a reason, a second line in `text.secondary` (6.77 / 7.57): the reason as written, never translated | Make live again |
| Open conflict | `triangle-alert` `warning` (6.29 / 6.12 on `bg.raised`, 3.0 for a glyph) | "May contradict {id}." (`kb.notice.conflict`); `{id}` a link to the other entry, tooltip its title and summary | This replaces it, Keep both |
| Open duplicate | `info` `text.secondary` | "Possible duplicate of {id}." (`kb.notice.duplicate`), the id a link as above | "Merge into {id}" or "Merge {id} into this" (below); Keep both |
| Any other reason | `info` `text.secondary` | The reasons, one line each, in the table's order (each a whole catalogue string, never joined into one sentence) | Mark as still true, when a reason is one it clears; else, for Topic closed, "Move to epic {name}" (or "Move to project {name}" for a topic outside any epic; the existing `kb.move_*` keys); else Mark as no longer true |

Why conflict alone takes `warning`: it is the one reason that says two things Claude Code reads disagree, so one of them steers it wrong today; every other reason means "maybe out of date". A superseded or retired entry shows no other reason (it is out of every briefing: nothing to check). A pair shows on both entries' pages, each naming the other.

*This replaces it* (`kb.this_replaces`; conflict). The open entry supersedes the other: the other becomes superseded with this entry as its successor, the pair is resolved. Toast "K-9 is now superseded by this." with Undo (`kb.replaced_toast`), since the other entry changes off screen. **Keep both** (`contact.keep_both`, reused) records the pair as distinct, so it never warns again for that pair; the notice goes; no toast. Editing either entry re-runs the check (below), which resolves or reopens the pair.

*Merge* (duplicate; the contacts pattern, components-contacts.md 5). From the notice, **the older entry survives** (the lower id: the one briefings, sources and the human already know), so the action names its direction: on the newer entry "Merge into K-4" (`kb.merge_into_id`), on the older "Merge K-11 into this" (`kb.merge_here`). The survivor gets one revision whose body is its text, a blank line and the other's body (the 800 limit applies to typing, not to a merge); it lives at the narrowest level that holds both, gets copies of the other's sources, and the other is superseded by it; the pair is resolved. Then the survivor opens in its editor (in a list, the survivor's row unfolds in edit mode and scrolls into view, the human having asked; from an entry page, the survivor's page opens in the editor) so the person can tidy the joined text; `Esc` keeps the merge as it is. Toast "Merged into K-4." with Undo (`kb.merged`). A save made while tidying is its own step and is undone first. After the undo window, unmerging is Make live again on the superseded entry, and the survivor's history restores its earlier body if wanted. "Merge into..." (`kb.merge_into`; row menu and palette, memories only) turns the palette into a picker of the live memories that share a scope with this one (its level, the levels above, the levels below), title first and summary as the path; `Enter` merges **this** entry into the chosen one, which survives whatever the ids.

*Make live again* (`kb.make_live`). On the notice, the row menu of a superseded or retired entry, and the palette. The entry returns to the live list and to Claude Code's briefings; its successor, if any, stays live too (the checker pairs them again if they still disagree). No toast on its page: the notice going is the feedback. In the "Superseded and retired" list the row stays in place, its title back in `text.primary`, until the chip changes.

*Superseded and retired list* (the chip "Superseded and retired", `filter.inactive`, set from the list's last row or the palette). Ungrouped, the most recent state change first. Rows are knowledge rows with the title in `text.secondary` (closed things are dimmed, as closed topics are in the tree, but `text.tertiary` is not allowed on a selected row) and an empty signal slot; they unfold and open as usual and show the Superseded or Retired notice. Search and the dropdowns work under the chip. Empty (reachable only from the palette): "Nothing is superseded or retired." (`kb.inactive_empty`).

*To check list* (the chip "To check", `filter.to_check`, replacing "Not updated for 90 days"; set from the Overview with Kind: Memories, or from the palette with every kind). Ungrouped, ordered by the entry's first reason in the table's order, then by verified date, oldest first. The scope line under the title counts what is listed ("Acta · 2 documents, 5 memories"). Empty: "Nothing to check." (`kb.to_check_empty`). Git reasons arrive after the store's, so the list can grow by a row a moment after it opens; a row is inserted in its place without moving the focused row (6.5, rule 5).

*Provenance* (entry page). Under the meta line ("K-7 · Updated 2 h ago by Claude Code"), 4, one **provenance line** in `type.small` `text.tertiary` (5.78 / 5.67 on `bg.base`), segments joined by " · ", each a whole catalogue string and each present only when it says something:
1. "Written by Claude Code 19 Nov 2026" (`kb.written.*`, reused; the long form of 10.2), only when the entry has changed since it was written (otherwise the meta line says it). For a Claude Code entry its tooltip has two lines: "A Claude Code session on T-12" (`kb.session.on`, or `kb.session.any` without a focus topic) and the full date of the write (10.2); a session is shown by its topic and time, never by its id.
2. "From topic T-12" (`kb.prov.from`): the topic Claude Code was working on when it wrote the entry; the id a link (`accent`), its tooltip the title; absent when that topic owns the entry (the Level row says it).
3. "On branch feature/kb" (`kb.prov.branch`, the name in `type.code` at 12): the branch it was written on; absent on the default branch, outside git, and when the Branch row below says it.
4. "Checked 2 Nov 2026 by Alexandre" (`kb.prov.checked.*`): only when the latest verification was a Mark as still true rather than a write.

A human-written entry never checked since has no provenance line. In an unfolded memory, the meta row ("Written by Claude Code 2 h ago · edited by Alexandre 10 min ago") gains segment 2 only; sources and branch are on the entry page.

*Properties added* (the Document or memory row of components-records.md 5, Properties block; each only when set, like Due):
- **Branch** (`kb.prop.branch`; a branch memory, ADR 0015, 4): the branch in `type.code` at 12 `text.primary`, then 8 and, when a reason applies, "merged" or "no longer exists" in `type.small` `text.secondary` (`kb.branch.merged`, `kb.branch.gone`). Tooltip "True only on this branch, in {folder}." (`kb.branch.tip`). Plain text, not a control: Claude Code sets it when it writes.
- **Sources** (`kb.prop.sources`), up to three, one line of 28 each, in the order given:
  - a record: its id in `type.code` at 12 `text.tertiary`, 8, its title as a link (`accent`, truncated, tooltip the full title); a timeline entry reads "{topic}, entry of 19 Nov" (`kb.source.entry`); a record this database lacks (an import without it) reads "A record not in this database" (`kb.source.missing`) in `text.tertiary`, not a control;
  - a commit: "Commit 9e92ba4" (`kb.source.commit`, the short id in `type.code`), a ghost control that copies the full id and reads "Copied" for 1.5 s (`common.copied`, as the meta line's id), tooltip "Copy commit id" (`kb.source.copy_commit`);
  - a file: its path in the repository in `type.code` at 12, middle-truncated, as stored, then 8 and, when a reason applies, "changed since checked" or "deleted or moved" in `type.small` `text.secondary` (`kb.source.changed`, `kb.source.gone`); a ghost control that copies the path, tooltip "{folder} · Copy path" (`kb.source.copy_path`).
  People do not add or edit sources (Claude Code names them when it writes; not requested). Merging copies the other entry's sources to the survivor.

*Also open in a session* (entry page). While another live Claude Code session has read or written this entry in the last 10 minutes (presence, ADR 0015, 6), one line under the provenance line, the page line pattern of components-app.md 5: `bot` 14 in `text.secondary`, then "Claude Code is working with this memory on T-51" (`kb.also_open.memory`, `kb.also_open.document`; without a focus topic `kb.also_open.memory_any`, `kb.also_open.document_any`) in `type.small` `text.secondary`; tooltip "Last read 2 min ago" or "Last changed 2 min ago" (`kb.also_open.read`, `kb.also_open.wrote`). It comes and goes with presence, never moves the page (6.5), and has no action: it says why a save now may meet a newer revision.

*Checks on the human's writes.* A memory the human creates or edits (title, summary or body) or moves is checked as Claude Code's writes are, and never refused: a conflict or duplicate found on save is recorded as an open pair, and its notice shows on the saved memory at once, so a pair has one way to be resolved whoever wrote it. "Same as" an existing memory shows as the duplicate notice.

*Saving over a newer revision.* The document and memory editors save with the revision they opened. If Claude Code wrote meanwhile: when the two changes touch different sections, the save is merged over the newer revision and toasted "Saved. Claude Code's changes to other sections are kept." (`kb.save_merged`; the merged text is not on screen, so the toast is the only way to know); when they overlap, or either side changed the whole body, the title or the summary, the editor keeps the human's text and shows the edit-conflict notice of 6.5, rule 4, with its keys (`conflict.notice`, `conflict.theirs`, `conflict.mine`); "Keep mine" saves on top, theirs stays in the history.

*Finding duplicates among existing memories.* The palette command "Find duplicate memories" (`cmd.kb_find_duplicates`) checks every live memory of the active project against the others off the UI thread (about a second for 1,000) and changes no entry: found pairs become open pairs and their entries take the mark. One toast at the end: "Found 3 possible duplicates." with Show (`kb.scan_found`, `kb.scan_show`; Show opens the knowledge base page with the "To check" chip), or "No possible duplicates found." (`kb.scan_none`). While it runs, the command is not listed.

*History labels* for the new change kinds, in the "what changed" slot (`text.secondary`; the French agrees with the entry's kind, hence `.document` / `.memory` pairs): "Marked as still true" (`history.verified.*`), "Superseded by K-21" (`history.superseded.*`, the id a link), "Retired" or "Retired: {reason}" (`history.retired.*`, `history.retired_reason.*`; the reason as written, truncated, full in the tooltip), "Made live again" (`history.made_live.*`), "Merged K-11 into this" (`history.merged`, the id a link). A revision that changed no text has no line counts; selecting it shows the text as of that revision, and "Restore this version" is not offered on it.

*Keys.* `V` Mark as still true (focused knowledge row, unfolded memory, entry page; the focused element wins, as in the Properties block, so `V` in a text field types). The other acts are reached by the row menu, the notice's ghost actions (`Tab` reaches them) and the palette (interaction.md 6.1). `J` / `K` and `Left` / `Right` behave under either chip as without one.

*Undo.* Each act above is one `Mod+Z` step of the project's undo (6.4): Mark as still true (the previous verified date and file records come back; the revision stays in history), Mark as no longer true and This replaces it (the entry live again), Make live again (the state and successor as they were), Keep both (the pair open again), Merge (the store's unmerge). Undo never reverts a state change Claude Code made: the human uses Make live again.
