# Acta design: chat, settings, data safety and updates

Part of the Acta design system. [DESIGN.md](../../DESIGN.md) is the index: direction, principles and the never-list; the review checklist is [checklist.md](checklist.md). Section numbers are shared across all parts.

## 5. Components (continued): chat, settings, data safety and updates

States, the focus ring and the controls used here (buttons, inputs, rows, menus, dialog, notice, empty state) are in [components.md](components.md).

**Chat panel** (a tool window; ADR 0009; Windows only for now: macOS has the link, like Linux, until the web view can tell the page's own navigations from its frames'). It shows claude.ai, the website, in the system web view. Acta never reads from the page, writes to it or styles it, so the page keeps claude.ai's own theme whatever Acta's is.
- **Header** (4.5): name "Chat", context "claude.ai" (plain text; no logo of Anthropic or Claude anywhere). Buttons: Open in browser (`external-link`), Reload (`rotate-cw`), `ellipsis` (Sign-in help, Sign out and clear chat data..., then the view menu of 4.8.4). The view's `minus` in the area header hides the area. Tooltips of these buttons always open upward, away from the web view, which would cover them.
- **Toggle**: `Mod+Shift+H`, the titlebar toggle, palette "Toggle chat". `Mod+4` focuses it. Showing the panel focuses the page inside it; nothing else ever gives it focus.
- **Placement**: the right sidebar by default, as the second tab after the terminal (4.8.13); like every view it can be moved to any area, split from the terminal's group to see both, and its web view is hidden during a drag (4.8.9).
- **States.** All but the live one are drawn by Acta on `bg.sunken` as an empty state at the top left of the panel (padding 16, text at most 480 wide).
  - *Not started* (the web view is created only when the user asks). Heading "Chat with Claude". Sentence: "claude.ai in a panel, signed in with your own account. Acta never reads the page." Buttons: "Open claude.ai here" (primary, tooltip "Uses about 400 MB of memory once opened."), "Open in your browser" (ghost).
  - *Starting*: the empty surface; after 400 ms one line, "Opening claude.ai...", in `type.small` `text.tertiary`.
  - *Live*: the web view fills the panel under the header. Acta draws nothing over it.
  - *Sign-in help*: a Notice at the top of the panel, above the web view, the first time the panel is live and whenever "Sign-in help" is chosen: `info`, "Sign in by email: open the link, then type the code it shows here. Google or Apple sign-in may be refused.", action "Got it".
  - *Under an overlay.* The web view is a native view above everything Acta draws, so while the palette, quick capture, a dialog, a menu or the sidebar overlay is open it is hidden. During a view or tab drag it is hidden the same way, with its own line (4.8.9). Its place shows `bg.sunken` and one line at the top left, "The chat is hidden while this is open.", in `type.small` `text.tertiary`. It returns at the same bounds, without animation, when the overlay closes. Toasts and tooltips are placed so they never reach into the panel.
  - *Web view missing* (Windows without the WebView2 runtime). Heading "The chat panel needs WebView2". Sentence: "WebView2 is not installed, so claude.ai cannot show here. Everything else works." Buttons: "Open claude.ai in your browser" (primary), "Get WebView2" (ghost; Microsoft's download page in the system browser), "Try again" (ghost).
  - *Could not open*: heading "claude.ai could not be opened here", the reason when known ("There is no connection."), buttons "Try again" (primary) and "Open claude.ai in your browser" (ghost). The panel never fails to a blank surface.
- **Sign out and clear chat data...** is a confirmed case of 6.4, because the profile cannot be brought back: "Sign out and clear chat data?", "This deletes the panel's cookies and site data from this computer. Your conversations stay in your Claude account.", Cancel, "Sign out and clear". Afterwards the panel is back to *Not started*.
- **Keyboard.** While the page has focus, keys belong to the page, `Mod+K` included. The short list Acta keeps, per platform, is in 6.1; the palette is reached with `Mod+Shift+K`.
- **macOS and Linux** (macOS for now, ADR 0009 changelog 2026-11-21): there is no panel and no titlebar toggle. "Open claude.ai in your browser" is a palette command and a row in Settings, and `Mod+Shift+H` runs it.

**Agent browser** (a view; ADR 0010; Windows only for now). Claude Code's own browser: a WebView2 in its own profile (`<data dir>/agent-browser`, never the chat's), driven over Acta's pipe by the `browser` tools of `acta mcp browser`. The human can look, click and type in it at any time; the agent's next snapshot sees the result. It never opens claude.ai, claude.com or anthropic.com.
- **Header** (4.8.4): name "Agent browser", context "driven by T-42" (the focus id of the Claude Code session holding the browser; "driven by Claude Code" without one; nothing while no session is connected), in `type.small` `text.tertiary`. Buttons: Stop (`square`, tooltip "Stop Claude Code"), which becomes Resume (`play`, shown selected, tooltip "Resume") while stopped, and `ellipsis` ("Clear browser data...", separator, then the view menu of 4.8.4). Tooltips open upward, as the chat's.
- **Under the header**, top to bottom, on `bg.sunken`: the **address field** (28 high, inset 8 x 4, `bg.raised`, 1px `border.strong`, `radius.sm`, `type.ui`; placeholder "Type an address and press Enter"); it shows the page's address after each load unless it has focus, and Enter opens what was typed (a bare host gets `https://`, `localhost` and `127.` get `http://`; what the policy refuses is not opened and stays in the field). Then the **activity line** (24 high, padding 0 x 12, `type.small` `text.secondary`, truncated): the agent's last action in words, "Claude Code clicked e19 button "Greet"", "Claude Code opened http://127.0.0.1:5173", "Claude Code is waiting for you"; absent until the first action. Then the notices below, then the page.
- **Highlight**: the element the agent clicks or types into is outlined for 300 ms inside the page (DevTools overlay: a blue border and a 15% fill; no script in the page). Screenshots are taken without it.
- **Busy dot**: while a call runs or a handoff waits and the view is not on screen, its view tab (when inactive) and its titlebar toggle show a 6 dot in `accent` (after the name on a tab, top right on the toggle). Agent activity never shows, focuses or moves the view by itself.
- **Toggle**: the titlebar toggle (`globe`), the Layout menu and the palette ("Agent browser: Show" and the move commands of 4.8.7). No key of its own. Showing the view does not create the web view; the first call or an address typed does.
- **Placement**: the right sidebar by default, third tab after Terminal and Chat (4.8.13); movable like every view; hidden during a drag with the 4.8.9 line.
- **States.** All but the live page are drawn by Acta at the top left under the address field (padding 16, text at most 480 wide), as the chat's.
  - *Idle* (no web view yet, or closed after 10 minutes unused off screen; the profile and its sign-ins stay). Heading "Claude Code's browser". Sentence: "Claude Code opens pages here when it needs a browser: your local dev server, or a site you signed into here. Sign in to a site once in this view and Claude Code reuses the session. It never opens claude.ai and never types passwords." Then, in `type.small` `text.tertiary`: "The browser starts on first use and uses about 150 MB of memory until it has been unused for 10 minutes."
  - *Starting*: the empty surface; after 400 ms "Starting the browser..." in `type.small` `text.tertiary` (creation is usually done before).
  - *Live*: the web view fills the rest of the view. Acta draws nothing over it.
  - *Under an overlay or a drag*: as the chat (Chat panel, above), with "The browser is hidden while this is open." or the 4.8.9 line. The web view is then **parked**, never hidden: visible, moved outside the window's client area at its size, so the agent's screenshots and clicks keep working (ADR 0010, decision 8). The same holds whenever the view is off screen (another tab active, its area hidden, a folded group).
  - *Stopped*: a Notice above the page, `square` in `text.secondary`, "Stopped. Claude Code is told to ask you before it continues.", action "Resume" (ghost). Until Resume, every call answers "stopped by the user; ask them before continuing"; Stop also cancels the call in flight, stops the page loading and ends a waiting handoff.
  - *Handoff*: a Notice above the page, `info`, "Claude Code asks you: {message}" (the agent's message, at most 200 characters), action "Done" (primary). Done answers the agent's call, which waits up to 10 minutes.
  - *Web view missing*: heading "The agent browser needs WebView2", sentence "Microsoft's WebView2 runtime is not installed on this computer, so Acta cannot open its browser. Everything else in Acta works.", buttons "Get WebView2" (primary) and "Try again" (ghost).
  - *Debugging port or override configured* (an `AdditionalBrowserArguments`, `BrowserExecutableFolder` or `UserDataFolder` WebView2 policy naming Acta; `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` asking for a debugging port, or `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER`, `WEBVIEW2_USER_DATA_FOLDER` or `WEBVIEW2_PIPE_FOR_SCRIPT_DEBUGGER` set; or a `DevToolsActivePort` file in either profile): heading "Acta did not start its browser", sentence "A debugging port or another WebView2 override is configured for Acta (a WebView2 policy, an environment variable or a DevToolsActivePort file). It could let another program control or read the browser. Remove it, then try again.", button "Try again" (secondary). The agent gets the reason in one line.
  - *Could not start*: heading "The browser could not be started", button "Try again" (primary).
  - *Not reachable by Claude Code* (the pipe could not be served): a Notice with `triangle-alert` in `warning` above everything else: "Claude Code cannot reach this browser: another copy of Acta, or another program, already serves it. Close it and restart Acta." (name taken) or "Claude Code cannot reach this browser. Restart Acta; the log says why." The view still works for the human.
- **Clear browser data...** is a confirmed case of 6.4: "Clear the browser's data?", "This deletes the cookies and site data of Acta's browser from this computer: you are signed out of every site you signed into there.", Cancel, "Clear data". Afterwards the view is *Idle*. If the files stay locked, toast: "The browser data could not be deleted. Close what may use it and try again."
- **Blocked by the policy, never shown to the human as an error**: schemes other than http(s), the Claude sites, credentials in URLs, downloads (cancelled), file choosers, JavaScript dialogs (dismissed), permission requests (denied), HTTP sign-in prompts (cancelled), links to other applications (never launched); frames are held to the same navigation rules. Pop-ups and `target=_blank` links open in the same view. Each is reported to the agent once, in its next reply.
- **Keyboard.** While the page has focus, keys belong to it, except the short list Acta keeps (6.1), routed as for the chat.
- **macOS and Linux**: no view and no toggle; the `browser` tools answer "Acta's agent browser is not available on this OS yet; use Claude in Chrome".

**Claude Code sessions** (session presence; ADR 0005 amendment of 2026-11-21, data.md request 2). Which Claude Code sessions run right now, at which level (topic, epic or project), on which record, and what they are doing, whether they were started in Acta's terminal or in any terminal inside an attached folder. Each session's `acta mcp` keeps one row in `presence.db` (local, never exported): its focus, a state, the time it started, the name of its last tool and an activity line taken from what the agent itself wrote to Acta (the text of its last `log`). Never a prompt, a tool's input or output, or file content. A session that stops sending its 30 s heartbeat is gone after 90 s.
- **States**, one glyph for all of them, `bot` (Lucide), coloured by state: *Working* (`accent`: a prompt was sent, a tool ran or a subagent started), *Waiting for you* (`warning`: a permission prompt or a question is open in the session), *Idle* (`text.tertiary`: the turn ended; the session is open). Several sessions on one record show one glyph in the strongest state, waiting before working before idle. The glyph is never animated.
- **Status bar.** While at least one session is live, the Claude Code item names the strongest state only, "Claude Code: 1 waiting for you" (else "2 working", else "1 idle"), with `bot` in that state's colour; its tooltip lists each state with its count, then the first session's focus and activity (layout.md 4.6). Click shows and focuses the Sessions view. With no live session the item is the setup status as before.
- **Tree.** The row of the record a session focuses (a topic, an epic, or the project row when it has no focus) shows `bot` 14 at its right end, before any count, in the colour of its state; tooltip "Claude Code is working here" / "Claude Code is waiting for you here" / "Claude Code is open here", then "since 14:05". One indicator per row, never on ancestors: the sidebar spec's "Claude working here" indicator is this glyph (for the designer of `product-designer/sidebar-clarity`).
- **Page line.** A topic, epic or project page that a live session focuses shows one line under the meta line, `type.small`: `bot` 14 in the state's colour, then in `text.secondary` "Claude Code is working here" (or "Claude Code is waiting for you here", "Claude Code is open here"), then, when the session runs in Acta's terminal, a ghost text button "Show terminal". "Since 14:05" and "last: {activity}" (clipped at 100 characters; without one, "last tool: Bash") are the line's tooltip, one per line, not on screen (clarity review 2026-11-22). Two or more sessions: "2 Claude Code sessions here" and the strongest state's colour; "Show terminal" goes to the one in Acta.
- **Sessions view** (a view: key `sessions`, icon `bot`, name "Claude Code sessions", default place the bottom panel, hidden by default; titlebar toggle after the agent browser's, the Layout menu and the palette "Claude Code sessions: Show"). One row per live session, newest activity first, 44 high, padding 8 x 12, the list's hover and selection: line 1, `bot` 14 in the state's colour, the focus as "T-12 Embed the terminal" (or "E-3 Storage", "project Acta") in `type.ui` `text.primary`, and at the right the state word in `type.small` in the state's colour; line 2 in `type.small` `text.tertiary`: "since 14:05 · last: {activity} · in Acta's terminal" (or "in another terminal"). Click or Enter opens the focus's page in the active tab. Right-aligned ghost buttons on hover and on the selected row, for sessions in Acta's terminal only: "Show terminal" (`square-terminal`) and "End session" (`x`; ends the terminal's process like closing it, no confirmation: the conversation is kept by Claude Code and comes back with the next start). A session outside Acta has no actions beyond opening its page: Acta never drives another terminal. Empty: "No Claude Code session is running." (`type.small` `text.tertiary`, padding 12). The context text of its header is the count ("3 running").
- **Terminal.** The terminal's header context names its session the same way: "Claude · T-12 Embed the terminal", and " · waiting for you" in `warning` while the session waits; when the session is not on screen, its view tab and titlebar toggle show the 6 busy dot (`accent`, the agent browser's) while it waits.
- **Waiting, outside Acta's window.** Setting "Flash Acta in the taskbar when a session waits for you" (Settings, Claude Code; off by default): when a session started in Acta's terminal starts waiting and no Acta window is active, the taskbar button flashes until Acta is activated. Windows only (the setting is not shown elsewhere). It never activates a window or takes focus.
- **Settings, Claude Code** (after the status row, Set up and the CLI path): "Continue the last conversation of each page" (on), "Show plan usage in the status bar" (on), and on Windows "Flash Acta in the taskbar when a session waits for you" (off); each a checkbox (components.md 5) as the setting row's control, and a palette command; the first two have no description (their labels say it, copy.md 7), the third "Only while Acta is in the background." While no usage report has arrived, the tooltip of "Show plan usage in the status bar" says why the bar shows none (`usage.no_data.tip`). The plugin line (`settings.plugin.hint`) is no longer a free paragraph between rows, where it read as part of the row above it: it is behind "What setup changes". "Set up Claude Code" asks first (dialog of 440, "Set up Claude Code?", Cancel and Set up): what setup writes, and "It also turns Claude Code's own memory off in 3 folders of Acta." for the open project's attached folders, the only ones it touches.
- **Starting Claude Code from Acta** (ADR 0008 amendment). The terminal starts `claude` in the page's primary folder with the other folders, the focus, Acta's plugin for that session (`--plugin-dir`, so Acta's tools and hooks are there even before setup) and the page's last conversation: setting "Continue the last conversation of each page" (Settings, Claude Code; on by default) resumes it when Claude Code still has it, else starts a new one. `/clear` in Claude Code starts a new conversation, which becomes the page's.

**Plan usage** (status bar, after the Claude Code item; ADR 0005 amendment of 2026-11-21). The two limits of the user's Claude plan as Claude Code last reported them to its status line command, `acta statusline` (the only documented source; Pro, Max and Ultra plans, after a session's first answer). Two compact meters, gap 0: "5h 42%" and "7d 18%" ("5 h 42 %", "7 j 18 %" in French) in `type.small` `tnum`, each followed by a 24 x 4 bar (`radius.xs`, track `fill.selected`, fill `text.secondary`). Above 80 %: text and fill in `warning`. A window whose reset time has passed since the number was seen is drawn in `text.disabled` (stale) and its tooltip says "This window has reset since Claude Code last reported it." Tooltip: "5-hour limit: 42% used, resets at 19:00" (today) or "7-day limit: 18% used, resets Mon 09:00". Before any report: nothing (clarity review 2026-11-22: a placeholder item in a bar that "never shows messages" was one); where the numbers come from is the tooltip of the Settings row while no report has arrived. Not interactive beyond the tooltip. Settings, Claude Code: "Show plan usage in the status bar" (on). Acta never asks claude.ai or Anthropic for these numbers and never reads Claude Code's files: when Claude Code has not run, the meters keep their last values, marked stale once their window resets.

**Ready for Claude Code** (ADR 0013; screens.md 8.26; keys `ready.*`, catalogue 10.4.8). What Claude Code needs on this computer, checked and, on the user's click, installed from the vendor or the system's package manager. A block, not a page: it heads Settings > Claude Code and, while a required or recommended row is not ready, the first-run page (above "Start with a project", same column).
- **Block.** Heading "Ready for Claude Code" in `type.label`; under it, `type.small` `text.tertiary`: "What Claude Code uses on this computer. Nothing is installed without your click." (where it comes from is in each install's confirmation, below) Then the rows, 8 apart, in this order: Claude Code, Signed in to Claude, Git, GitHub CLI (only when an attached folder has a `github.com` remote, or `gh` is found; never on first run). Then a ghost "Check again" (`rotate-cw`), disabled during an install.
- **Row** (min 44, padding 4 x 0, the setting row's layout): glyph 14 at the left; line 1 the name in `type.ui` `text.primary`, then the state in `type.small` at the right before the action; line 2 the why in `type.small` `text.tertiary` (one line, wraps under 520). The action is one button at the right: secondary for a required row, ghost for recommended and optional ones; the first required row not ready gets the primary instead, and then "Set up Claude Code" below is secondary until it is ready.
- **States** (glyph, state text, action):
  - *Found*: `check` in `success`; "2.1.330" (`tnum`), Git on Windows "2.56.1 · with Git Bash", or "2.56.1 · without Git Bash: Claude Code will use PowerShell" in `text.secondary`; no action. Signed in: "Signed in"; or "Using an API key" in `text.secondary` (not an error; the tooltip says Acta works best with a Claude subscription).
  - *Missing*: `circle-dashed` in `text.tertiary`; "Not installed" (optional row: "Not installed · optional"); "Install..." Signed out: "Not signed in"; "Sign in..." (requires Claude Code found; disabled with the tooltip "Install Claude Code first" otherwise).
  - *Outdated*: `triangle-alert` in `warning`; "2.1.100 · 2.1.329 or later needed"; "Update..." when a one-command update exists for its install kind, else "Show command".
  - *Installing* (or updating): `circle-dashed` in `text.secondary`, no motion; "Installing... 0:42" (elapsed, `tnum`, updated each second; nothing shown before 400 ms); the action is "Show log" (ghost). Other rows' actions are disabled with the tooltip "One install at a time".
  - *Waiting for the terminal* (Linux root installs, sign-in): `square-terminal` in `text.secondary`; "Finish in the terminal"; "Show terminal". The row re-checks when that terminal session ends and on focus.
  - *Waiting for macOS* (`xcode-select --install`): `circle-dashed` in `text.secondary`; "Finish in the macOS window"; no action; re-checks on focus.
  - *Failed*: `triangle-alert` in `danger`; "Install failed"; actions "Retry" (`common.retry`) and "Show log" (ghost). Under line 2, in `type.small` `text.secondary`: the reason ("The installer stopped with code 1603." / "Installed, but Acta cannot find Git yet. Restart Acta."), and for Claude Code on Windows with winget present a ghost "Install with winget instead".
  - *No package manager*: `circle-dashed`; "Not installed"; "Open download page" (`external-link`, the official page in the system browser).
  - *Could not check*: `circle-dashed` in `text.tertiary`; "Could not check" (`settings.check.unknown`); tooltip the one-line reason; "Check again".
- **Log.** "Show log" expands, under the row, a read-only `type.code` block (max 200 high, scrolls, follows the end while running unless the user scrolled up), last 400 lines, control sequences stripped; a ghost "Copy log" and "Hide log". In memory only, gone when Acta quits.
- **Confirmation dialog** (6.4, width 440; Cancel focused): title "Install Git?" ("Update Git?"); body, one sentence each in `type.reading`: where it comes from (`ready.from.*`), the scope (`ready.scope.*`), who updates it (`ready.updates.*`); then "Command" in `type.label` and the exact command in a `type.code` block with "Copy command"; buttons Cancel and "Install" ("Update"; "Open in terminal" for a command that runs in Acta's terminal). Nothing runs before the button.
- **Status bar.** While a required row is not ready, the Claude Code item reads "Claude Code: not installed" or "Claude Code: not signed in" (before any setup status) and opens Settings scrolled to the block.
- **Never**: an install at startup, in the background, or chained to another; a progress bar for something whose length is unknown; a toast for what the row already shows; any input sent to a window other than the Acta terminal session the user opened with the button.

**Settings page** (a page like any other: `Mod+,`, the Settings row of the sidebar, or the palette; it opens in the active tab). Title "Settings". Sections are headed in `type.subtitle`, 32 apart. A **setting row** is at least 44 high with 8 of vertical padding: at the left the label in `type.ui` `text.primary` and under it a description in `type.small` `text.tertiary` (at most 420 wide, wraps); at the right the control. No boxes, no lines. Every setting applies the moment it changes, has no Save button, and exists as a palette command.

**Snapshot restore** (palette: "Restore from snapshot..."): dialog of 520, titled "Restore from snapshot", listing snapshots, newest first, rows of 32: date and time (`tnum`), kind ("Daily", "Weekly", "Before update to 0.4.1", "Before import", "Before restore"), size. Selecting one enables the destructive-styled button "Restore and restart" and shows: "Acta will restart with its data as of 18 Nov 2026, 09:12. Everything as it is now is saved as a snapshot first, so you can come back." This is one of the confirmed cases in 6.4. After restart a notice reads "Restored the snapshot from 18 Nov 2026, 09:12." If a migration fails after an update, Acta restores by itself and the next launch shows the notice "The update to 0.4.1 could not convert the database. Acta put back the snapshot from just before; nothing was lost." with the action "Details".

**Key-loss recovery screen** (replaces the whole window content, like first run; see 8.9). Shown when the database file exists but its key is not in the system keychain. Calm and exact: no red, no icon larger than 16, no "error" in the heading. It states what is true (the file is intact, unreadable, untouched), why it usually happens, and offers three actions in order of safety: "Import an export..." (primary), "Try again" (secondary; re-reads the keychain, for a locked or slow keychain), "Start empty" (ghost; the unreadable file is renamed and kept, the screen says its new name). Acta never creates a database over the old one and never deletes the kept file.

**Updater window** (ADR 0004). An update is normally applied at launch, before the main window: a feed check of up to 2 s, a download of up to 5 s, then a relaunch. So that the user never stares at nothing, if the main window is not ready 300 ms after launch a small window appears at once and closes in the frame the main window opens. 360 x 132, centred on the primary display, not resizable, no caption buttons, draggable anywhere, `bg.base` with a 1px `border.default` outline (`radius.xl` where the platform allows a shaped window), padding 24, in the theme and language of the preferences file. Top to bottom, left-aligned: the app mark 24 and "Acta" in `type.ui-strong`, gap 8; 16; one status line in `type.ui` `text.primary`; 12; a progress bar (full width, 4 high, `radius.xs`, track `fill.selected`, fill `text.secondary`) with the percentage in `type.small` `text.tertiary` `tnum` right-aligned under it. The status line reads, in order, "Checking for updates..." (no bar: nothing is measurable yet, and an indeterminate bar would be animation for its own sake), "Downloading update..." (bar and percentage, updated as data arrives, never eased), "Restarting..." (bar full). There is no button and nothing to cancel: every step is bounded by ADR 0004, and when a step fails or runs out of time the window closes and Acta opens as it is, with no message. The app mark appears here at 24 and, on Windows and Linux, at 16 at the left of the main window's titlebar (4.3); nowhere else.
