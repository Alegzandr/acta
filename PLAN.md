## Memory quality (ADR 0015)
Requested by the user on 2026-11-22 (an endorsed critique: the agent's memory must handle stale information, contradictions, semantic duplicates, context changes, provenance and concurrent sessions; "memory quality will largely determine the product's quality"). Decided in ADR 0015 (proposed) on `integration-engineer/memory-quality-adr`. Detection is lexical and local; the agent judges; nothing is deleted or hidden automatically. No new tool; `tools/list` must not grow (new `kb_write` fields paid by trims in the same change).
- [x] Phase 1, store (`acta-core`, integration-engineer): schema 7 (`verified_at`/`verified_by` backfilled, `state`, `superseded_by`, context and provenance columns, `kb_revisions.session`/`branch`, `kb_links`, `kb_pairs`, local `kb_quality_log`, `kb_verified` index); `kb_verify`, `kb_supersede` (one transaction with the successor's write), `kb_retire`, `kb_make_live`, `kb_merge` (survivor revision, links copied, wider level, pair resolved); verified date set only by content writes; the Overview count on `verified_at` and live state; export format + 1 with the old-version import test. Tests: backfill, every state change and its undo, superseded and retired left out of `kb_scope` and search but readable by id, merge at the wider level, round trip. Done on `integration-engineer/memory-quality` (`store/kb.rs`, `store/kb_quality.rs`, schema V7, export format 5): `kb_create_with`/`kb_update_with` take a `KbWriteCtx` (session, focus topic, branch, context folder and branch, sources); `kb_supersede` takes the successor's write (`KbSuccessor::Create` or `Update`) and supersedes one to three live entries of the same project in its transaction; verify, retire (reason as the revision's `section`, 200 chars), make live and merge each write a revision with the text unchanged (new change kinds `verified`, `superseded`, `retired`, `made_live`, `merged`); `kb_merge` returns a `KbMergeTrace` and `kb_unmerge` takes it back in one step (refused once the survivor changed); merge lives at the narrowest owner holding both (two topics of one epic: the epic). Sources (`kb_add_links`, `kb_links`: records by UUID, commits, repository-relative paths with folder and blob); pairs (`kb_record_pair` keeps a `distinct` decision, `kb_set_pair_state`, `kb_pairs_of`); the local log (`kb_log`, `kb_log_since`, pruned at 180 days, never exported). Rows an older build writes have no verified date: every read falls back to `updated_at`. Note: a 0.6 build reading the history of an entry with one of the new change kinds fails on that history page (the enum is closed); the entry itself still reads.
- [x] Phase 2, checker (`acta-core::kb_quality`, pure functions): normalisation (NFKD, en and fr stop words and suffixes), trigram and token Jaccard, the conflict signals (polarity, antonyms, values), FTS prefilter over owner, ancestors and descendants; `kb_flags` for the store flags. The labelled fixture (80+ pairs, en and fr, Alexandre) with precision and recall printed and asserted at the ADR targets; a 2,000-memory timing reported.
