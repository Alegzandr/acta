# Contributing to Acta

Thank you for taking the time. Acta is pre-alpha and moves milestone by milestone
([PLAN.md](PLAN.md)), so the most useful contributions right now are bug reports from
installing and updating on your system, and ideas that fit the plan.

## Issues

- **Bugs:** use the bug form. Say which system, which Acta version (shown in the status
  bar) and what you expected. The log is `%LOCALAPPDATA%\ActaData\logs\acta.log` on
  Windows, `~/Library/Logs/Acta/acta.log` on macOS and `~/.local/state/acta/acta.log` on
  Linux; it holds no user content, but read it before you paste it.
- **Ideas:** use the feature form. Say what you are trying to do, not only the feature.
- **Security problems:** never in a public issue; see [SECURITY.md](SECURITY.md).

For anything larger than a small fix, open an issue before writing code, so we can agree
on the approach first. Architecture choices are recorded in
[docs/decisions/](docs/decisions/) and the interface follows [DESIGN.md](DESIGN.md); a
change that departs from either updates that file in the same pull request and says why.

## Building

See [Build from source](README.md#build-from-source) in the README. In short: install Rust
with rustup (the toolchain is pinned), then `cargo run -p acta-app`.

## Before you open a pull request

All three must pass; CI runs them on Windows, macOS and Linux:

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

- Keep a pull request to one change. Small is easier to review and to revert.
- Never write user data, key material or secrets in plain text to disk, logs or process
  arguments.
- Sample and test data uses the name "Alexandre".

## Commits

- English, for code, comments, docs and commits.
- An imperative subject line that says what the commit does ("Add the topic status
  menu"), at most about 70 characters, with a body when the why is not obvious.
- No co-author trailers for AI tools and no "generated by" lines. You are the author of
  what you submit.
